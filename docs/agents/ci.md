- **`pnpm verify:full` is the gate, and its last line is the answer.** Every caller runs this one command: you, `.githooks/pre-push`, and CI (`docs/04` §5). `pnpm verify` is the browser-free chain inside it, so `e2e/**` is invisible to `verify` alone. `verify:full` runs `verify` and then the browser check, and prints one verdict line: `verify:full PASS — …` or `verify:full FAILED at check N of M: …`. Report that line, never `EXIT: $?` — a run with no verdict line is unproven, not green. Capture it with a redirect: `pnpm verify:full > /tmp/v.log 2>&1; tail -3 /tmp/v.log`. A pipe (`| tail -4`) makes `$?` read `tail`, which prints `EXIT: 0` over a failure. On #142 two agents reported `verify` green over a fully red `e2e/resize.spec.ts`. Both told the truth. The pre-push hook caught it after the review and after the merge (#255, `docs/04` §3.2).
- **Never poll CI by hand. `pnpm pr-wait <n>` is the one command, and its last line is the answer.** It watches the CI workflow run for the pull request's head commit (`gh run watch`), ignores skipped draft-time jobs, and prints `pr-wait PASS — …` or `pr-wait FAILED — …`. A draft runs nothing (#255). A `workflow_dispatch` run proves the gate and cannot close a `pr-wait` — push a commit so `synchronize` fires (`docs/04` §5.2). Report the verdict line, never an exit code.
- **A ready pull request with no run at all — push a commit.** `ready_for_review` is a listed trigger (`.github/workflows/ci.yml:23`), and the run still does not always appear. It has failed to fire on the last several pull requests. `pnpm pr-wait` then says "no live pull_request gate run", `gh pr checks <n>` says "no checks reported", and `gh run list` shows nothing on the head sha. Check that Actions itself is healthy before you chase it: `gh run list --limit 5` unfiltered shows other branches running in the same minutes. **`synchronize` is the one event that reliably starts the run, so push a commit.** Two things that look like fixes are not: `gh pr close` then `gh pr reopen` fires nothing, although `reopened` is a listed trigger (measured on #482, 2026-09-22), and a `workflow_dispatch` run proves the gate but cannot close a `pr-wait` (above). Prefer a commit that carries real work. `git commit --allow-empty` is the last resort, and it leaves a no-op commit in the branch forever.
- **`verify`/`lint`/`typecheck` output truncation.** `pnpm verify 2>&1 | tail -100`-style commands get re-run many times (seen 17x, 13x, 25x in one session) chasing truncated output, at ~25,000 tokens/session. Use the `verify:full` redirect-and-verdict pattern above; for `lint`/`typecheck`, redirect to a log file once and `grep -n "FAIL\|error"` it instead of re-running with a longer `tail`.
