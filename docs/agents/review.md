- **`ocr` is the branch reviewer.** It is `@alibaba-group/open-code-review`, installed at `/home/pawel/.npm-global/bin/ocr` (a symlink to `../lib/node_modules/@alibaba-group/open-code-review/bin/ocr.js`). Review this branch only with `ocr review --from origin/main --to HEAD` — diff against `origin/main`, never local `main`, which goes stale. Add `--preview` to list the files first; it skips Markdown and `*.test.ts` by its own rules. It sends the diff to a configured LLM provider.
- **An `ocr review` run takes 10 to 30 minutes. That is normal, not a hang.** A foreground tool call stops at 10 minutes, so run it in the background under `timeout 1800`. Wait for its completion notice. Do not poll it. Never kill it before the 30 minutes pass.
- **A plan or review's account of the code is a claim. Open the file before you act on it.** A verified finding does not verify its proposed fix. In one case all 18 findings were real, but one report described the code wrongly, and the true fix was smaller. Probe behaviour with a throwaway test before any "changes no reader" refactor. Delete the probe. Then pin the behaviour with a real test. Two earlier cases where defaults were overlooked cost a silent regression each.
