- **`ocr` is the branch reviewer.** It is `@alibaba-group/open-code-review`, installed at `/home/pawel/.npm-global/bin/ocr` (a symlink to `../lib/node_modules/@alibaba-group/open-code-review/bin/ocr.js`). Review this branch only with `pnpm ocr-review` — it diffs against `origin/main`, never local `main`, which goes stale. Add `--preview` to `ocr review --from origin/main --to HEAD` to list the files first. That skips Markdown and `*.test.ts` by its own rules. It sends the diff to a configured LLM provider.
- **Run `pnpm ocr-review` in the background.** A foreground tool call stops at 10 minutes. A run of 10 to 30+ minutes is normal, not a hang. Fix findings as they land — the script prints each one, and `ocr session comments <id>` reads them again at any time. The script kills a run only after 15 minutes pass with no new finished file and no new finding, and reports STALLED. A PARTIAL run names the files that failed; rerun with `pnpm ocr-review --resume <id>`.
- **A plan or review's account of the code is a claim. Open the file before you act on it.** A verified finding does not verify its proposed fix. In one case all 18 findings were real, but one report described the code wrongly, and the true fix was smaller. Probe behaviour with a throwaway test before any "changes no reader" refactor. Delete the probe. Then pin the behaviour with a real test. Two earlier cases where defaults were overlooked cost a silent regression each.
