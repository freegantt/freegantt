Who may import whom

.dependency-cruiser.cjs transcribes the diagram literally: one forbid() rule per layer, listing its only legal targets. Anything not listed fails the build (invariant I1).

layer may import note
model — nothing — Leaf. Types plus entryId/rowId/itemId and FreeGanttError.
time model Plus the one runtime dep temporal-polyfill, confined to zone.ts.
layout time, model Where the shareable viewport models live — the only DOM-free layer both allowed time/ and reachable from view/.
scheduling time, model Stub. Never imported by data/ statically — they meet at the resolve hook.

The five custom lint rules. eslint/rules/ holds what dependency-cruiser cannot see, all scoped to src/**: no-date-outside-time, no-magic-time-constants, no-instant-arithmetic (I10 — time/ is the only place Date.now(), 86400000, or a - b on two Instants is legal), no-time-to-pixel-math and no-scroll-outside-scroll-model (I12 — view/scroll-attachment.ts is the single exempted file). Each rule ships a violation fixture under test/fixtures/ so the rule itself is proven to bite.

Every non-test file in src/, with the one thing it is for. Barrels (index.ts) are listed only where they do something beyond re-export.

model/  pure  types + brand helpers, zero deps
model/ids.ts EntryId, RowId, ItemId, entryId(), rowId(), itemId() Branded string ids. itemId(entry, seg) is the deterministic `${entryId}:${segmentIndex}` rule (I8) — the one place that format is written.

time/zone.ts toPlain(), fromPlain(), startOfDay(), addDays(), addMonths(), addYears(), diffDays(), stepBy(), startOf(), SUPPORTED_TIME_UNITS All zone-aware arithmetic, on temporal-polyfill's tree-shaken /fns API. 3Construction: the call sequence

new Gantt({ container, dataset }) is six lines of forwarding and then one long constructor. Everything below happens synchronously, in this order, before the constructor returns.

derived from harness/main.ts, api/gantt.ts, view/gantt-shell.ts, layout/viewport/viewport.ts, render/dom/index.ts

Why the order is what it is

step the constraint that forces this position
6–7 Mount before bind. The binding's own onChange is this shell's first render, so the render target must already exist when it fires. Doing it this way removes the "call render() yourself after bind()" step that would otherwise be a construction-order exception in the docs.
8 Before either bind, so #scrollAttachment can never be undefined during a render. The container element is the timeline pane and the single native scroller — there is no second scroller to keep in sync, which is why nothing can fall a frame behind.
9–11 bind() always notifies the newcomer (that is its first render), once per sub-model. Those two calls land before #viewportHandle is even assigned, so #wiring swallows them. See §9-B.
12 One synchronous measurement, because a real ResizeObserver's first callback is queued, not immediate — the first paint cannot wait for it. --fg-row-height is re-read here rather than per render, because getComputedStyle forces a style recalculation and a resize is the only realistic moment the value changes.
13 rowLabelWidth is subtracted here, once, so every consumer of "pane width" — TimeScaleModel's zoom fit, ScrollModel's max, visible.width — agrees on the width that is actually drawable.

4One render pass

GanttShell.render() is fourteen lines and the entire hot path today. It gathers six inputs, runs one pure function, hands the result to the backend, then pushes the resulting extents back into the viewport — which is where it gets interesting.

derived from view/gantt-shell.ts render(), layout/frame.ts, layout/frame-layout.ts, render/dom/index.ts sync(), view/scroll-attachment.ts

The two coordinate rules computeFrame keeps

  • Windowed vs. full. rows and bars hold only what survived culling; contentWidth/contentHeight are always the full extent. That split is what lets the scroll model compute a real maximum from a frame that drew twelve rows out of two thousand.
  • Zero disables culling. A zero visible.height means "no culling at all", not "an empty window" — and likewise for width. Without that rule an unmeasured container (detached, display:none, pre-paint) would silently render nothing.
  • Overscan is in index space vertically, pixels horizontally. Vertical overscan counts rows and goes through the height index, so it stays correct when S5 makes row heights vary. Horizontal has no rows to count, so it is a pixel buffer.
  • Rows are culled vertically only. A row whose bar is off-screen horizontally is still emitted — the grid pane needs its label.

5The notification machine

Four classes, layered, each one strictly smaller than the one above. This is the most intricate part of the codebase and the part most worth understanding before changing anything in layout/viewport/.

derived from layout/viewport/batched-notifier.ts, bound-value.ts, time-scale-model.ts, scroll-model.ts, viewport.ts

The one contract everything here implements (D-S1.5-4): bind always notifies the newcomer; every other notification fires if and only if the resolved value actually changed. A newcomer's notification is its first render, so it does not wait for an open batch. A departing binding is never notified of its own departure; the survivors are, if the value moved without it.

The four layers, smallest first

class knows about deliberately does not know about
BatchedNotifier a depth counter, a pending flag, one deliver callback bindings, values, what "changed" means. It is the whole batching mechanism and nothing else.
BoundValue<B,V> the binding set, the memoized resolved value, the last-notified value, and the notify-iff-changed rule time, scroll, pixels. It takes resolve and equals as a contract and has no opinion on either.
TimeScaleModel / ScrollModel what to resolve from a binding set, and what counts as a change each other, and the DOM. They differ only in those two functions.
Viewport one Gantt's pane size, content size and overscan; fans both models into one reaction how either model resolves anything. It uses BatchedNotifier alone — it has one subscriber and no value of its own to compare, so BoundValue's comparison half would be a capability it must not have.

Where the batches nest

Viewport.batch(run)
  └─ Viewport.#notifications.batch(          // coalesce the consumer reaction
       scale.batch(                          // coalesce within TimeScaleModel
         scroll.batch(run)))                 // coalesce within ScrollModel

Viewport.setPaneSize(size)                   // one measurement, two models
  └─ #notifications.batch(() => {
       scaleHandle.setPaneWidth(size.width)  // may notify
       scrollHandle.setPaneSize(size)        // may notify
     })                                      // → at most ONE render()

Without Viewport's own batching layer, a single resize would deliver two notifications for one caller-visible change: the two models dedupe within themselves, but neither knows the other was touched by the same call.

The binding side both models share. Scoped to layout/viewport/ on purpose — it must not grow into a general reactivity primitive. When a shareable model needs more than "call my reaction when I might be stale", that is the signal to consolidate under data/'s alien-signals façade instead.

The layout pass. Pure, stateless, no allocation beyond the arrays it returns. S0/S1 scope: flat row-per-entry, one bar per entry, fixed row height — S5 brings lanes, grouping and segments.

7Class map: time/ & model/

derived from src/time/**, src/model/**, docs/adr/0001

The time pipeline

Everything that turns a date into a pixel goes left to right through here. Nothing outside time/ is allowed to shortcut it.

model/ pure

Six files, all types, plus three id helpers and two error classes. That is the entire runtime — the layer exists so layout/, render/ and view/ share one vocabulary without depending on each other.

type shape the rule it encodes
Instant number & {__brand} Epoch ms. Branded so a naked number cannot be passed as a date by accident.
TimeSpan { start, end } Half-open [start, end) in storage. Display is inclusive, via one formatting helper — never an inline end - 1.
EntryId / RowId / ItemId string & {__brand} Three distinct brands over string, so a row id cannot be used where an item id belongs.
Entry id, parentId?, kind?, name, start, end, progress?, segments?, meta? kind is authored, never derived from having children. meta is consumer-owned and typed through the generic.
EntryKind 'span' | 'group' | 'milestone' | (string & {}) Open union: the (string & {}) arm keeps editor autocomplete on the three shipped kinds while still accepting consumer-defined ones.
Dataset { entries, timeZone } The structural contract. api/dataset.ts's class implements it, which is what lets layout/ bind against a dataset without an illegal import.
Rect / Size / Point / PixelSpan readonly numbers One geometry vocabulary for four layers.
InstantInput Instant | Date | number | string The input twin of Instant: what a consumer may write where the library stores an Instant. A string is either absolute (explicit Z or numeric offset) or a Plain time that names no instant until the Dataset's zone resolves it.
EntryInput / TimeSpanInput the loose twins Same fields, looser types: plain-string ids, InstantInput dates. Because EntryId is string & brand and Instant is number & brand, a stored Entry is itself a valid EntryInput — the pass-through case costs nothing.
DateOnlyEndRule 'inclusive' | 'exclusive' Reconciles half-open storage with what a consumer means by a bare date on end. A consumer writing end: '2026-09-08' means "through the 8th"; storage needs the boundary after the span. 'inclusive' (default) advances such an end by one calendar day; 'exclusive' reads it literally. Only date-only strings are affected — anything carrying a time of day is already a boundary.

8Class map: render/ & api/

derived from src/render/**, src/api/**, harness/main.ts

Reading what a consumer writes: EntryInput → Entry

ahead of main this subsection describes src/model/time.ts, src/time/input.ts and src/api/entry-input.ts as they stand on branch host-input-dates-and-ids (de5d755) — not yet merged

The library stores branded, absolute values; a consumer writes loose ones. Exactly one crossing turns the second into the first, and it happens once, in the Dataset constructor.

Why the split is where it is. api/entry-input.ts may see both model/ (for the brand helpers) and time/ (for the reading) — it is the only layer permitted both. But it does no date math itself: resolving a Plain time needs the zone and the DST fold/gap policy, and advancing a date-only end by "one day" is zone-aware arithmetic that is not always 86 400 000 ms. Both belong to time/ under I10. The rule to carry forward when touching either file: api/ maps fields, time/ decides dates.

What the DOM backend builds

container ← GanttShellOptions.container; ALSO the single native scroller ├─ div.fg-header position:relative; margin-left: rowLabelWidth │ └─ div.fg-band one per preset.headers entry, coarsest first — keyed by index │ └─ div.fg-tick keyed by index within the band; translateX + width + text ├─ div.fg-rows position:relative; width: rowLabelWidth → the label gutter │ └─ div.fg-row keyed by RowId; translateY + height + label text ├─ div.fg-bars position:relative; margin-left: rowLabelWidth │ └─ div.fg-bar keyed by ItemId; data-item-id + data-kind + translate() + w/h └─ div[aria-hidden] the content sizer — 1×1px, invisible, translated to the frame's bottom-right corner minus 1px on each axis
Two details that are load-bearing, not incidental. margin-left, not left, on the bar and header layers: an offset property shifts a relatively-positioned box without shrinking its auto width, so the layer would overflow the container by the gutter width on the right — which is exactly the phantom horizontal scroll range that once showed up as a blank gap past real content. And the content sizer must land its far edge on the content extent, hence the − 1: it is 1×1px, so translating its origin to the extent would make the browser's native scroll range one pixel longer than what ScrollModel computed.
createDomBackend() factory
render/dom/index.ts

A closure, not a class — the eight caches and five layer references are private by construction. Implements RenderBackend<HTMLElement>.

mount(el)
Reads --fg-row-label-width once, builds the four layers plus the sizer. The backend owns where the gutter sits for the life of the mount, so header ticks and bars are shifted by the same offset — a consumer stylesheet cannot move one without the other.
sync(frame)
Four syncKeyed passes plus one transform on the sizer. No layout reads.
applyState(state)
Empty. The hot path (hover/selection/drag preview) lands in S4: class toggles and transforms only, zero allocation, never a frame rebuild.

The single source of truth for the gutter. Callers that feed a pane width to TimeScaleModel must subtract it first, or ticks and bars end up computed against the wrong width and sitting in different coordinate frames.
syncKeyed() function
render/dom/sync-keyed.ts

The entire reconciler, in 30 lines. Three phases per call: look-up-or-create by key → patch only if toGeom differs from the cached geometry → prune keys no longer present.

nodes / geoms
The caller's persistent per-layer caches. They must survive across calls for reconciliation to do anything — a fresh Map per call would patch every node and never prune. §9-D

Called once per key. Attributes fixed for the node's lifetime (a bar's data-item-id) belong here, not in patch.
shallowEqual(a, b)
Exact, not approximate: every TGeom is a Pick<…> of primitive fields. §9-C
readPixelProperty() function
render/dom/pixel-property.ts

Level 1 of the customization ladder: read a --fg-* custom property off the container, parse to px, validate against what the library can actually draw with.

policy.accepts
'positive' — zero is nonsense (a zero-height row is not a row). 'zeroOrMore' — zero is a real choice (a consumer turning the label gutter off). Before this, the two properties were the same routine with silently different validity rules.
re-read cadence
The caller's, and each states it: gutter width once at mount; row height on every pane measurement. Neither per render — getComputedStyle can force a style recalculation.

view/ reads through this too; view → render is an allowed edge.

9Smells

Ten findings from following the call graph. None of them breaks anything today. They are ordered by how much they will cost when the area is next touched, and each names the file and the exact condition under which it becomes a bug.

derived from a full read of src/**; A verified by measurement — see §10

§9-A Every content-size change runs the layout pass twice, re-entrantly

view/gantt-shell.ts render() · layout/viewport/viewport.ts setPaneSize/setContentSize

render()'s fourth statement is #viewportHandle.setContentSize(#contentSize). When the content size actually changed, that invalidates ScrollModel, whose max moves, which notifies Viewport, which calls the shell's onChange — which calls render() again, synchronously, nested inside the first pass, before that pass has reached its last statement.

Measured: constructing a GanttShell calls FrameLayout.computeFrame 2 times, not 1. A later render() whose content size is unchanged costs 1. So the doubling lands on exactly the expensive renders — first paint, a zoom change, a row-count change — and not on the cheap ones.

It is not pure waste, which is the problem. The second pass is partly load-bearing: visible is clamped against #contentSize, so pass 1 culls against a window computed from the previous content extent. The second pass is what corrects it. That behaviour is real and nothing states it — no comment, no test. It also means pass 1's backend.sync() output is immediately overwritten by pass 2's, and pass 2's writePosition() runs before pass 1's.

Why it terminates: only by accident. contentWidth comes from scale.contentWidth and contentHeight from heights.totalHeight — neither depends on visible, so pass 2 produces the same extents and the notify-iff-changed rule stops the recursion. The day any part of content extent starts depending on the culling window, this becomes an infinite loop with no guard in the path.

Worth doing: make the two passes explicit — resolve the window against the new extents before drawing, so one render() is one frame — or, failing that, add a re-entrancy depth guard and a test that pins the pass count.

§9-B Boot ordering is held by a boolean, not by structure

view/gantt-shell.ts #wiring

The invariant is "no render happens until backend, scroll, viewport and the first pane measurement are all wired". It is enforced by one field that is true for the length of the constructor. The field is now well named — it says what phase it guards, which the older ready did not — but it is still a flag: reordering two constructor statements would produce a render against a half-built shell, or a dropped first render, with nothing failing loudly.

The structural fix is the usual one — a private #wire() that returns the fully-built collaborators, with render() unreachable until it has returned — but it is worth doing only when S2 or S4 adds a fourth thing to wire, not before.

§9-C shallowEqual compares one direction only

render/dom/sync-keyed.ts

for (const key in a) if (a[key] !== b[key]) return false never looks at keys present in b but absent from a. Today every geom for a given layer comes from one toGeom that always returns the same key set, so the comparison is exact and the docstring's claim holds.

It stops holding the first time a toGeom becomes conditional — { ...base, ...(flag ? { tint } : {}) } is the obvious S4 shape for hover and conflict flags. Then a transition from "has tint" to "has no tint" compares equal and the node is never repatched: a stale tint that persists until something else about the bar moves. A Object.keys(a).length !== Object.keys(b).length guard closes it, or the type could forbid optional fields outright.

§9-D Eight parallel caches that must be cleared in lockstep

render/dom/index.ts

bandNodes/bandGeom, bandTickNodes/bandTickGeom, rowNodes/rowGeom, barNodes/barGeom — four conceptual keyed layers stored as eight Maps, because syncKeyed takes nodes and geoms as two separate parameters. destroy() has eight .clear() calls that must stay in sync by hand, and syncHeader carries its own manual prune loop for the per-band tick caches alongside the pruning syncKeyed already does for the bands themselves.

One KeyedLayer<TKey, TGeom> holding both maps behind syncKeyed(layer, items, cache, spec) collapses eight fields to four, removes four clear calls, and makes the nested band/tick case a KeyedLayer that owns a Map of child KeyedLayers — which is what the manual prune loop is hand-rolling today.

§9-E Interfaces written ahead of their only consumer

layout/row-height-index.ts · layout/frame-layout.ts · render/backend.ts

RowHeightIndex.heightAt and RowHeightIndex.invalidateFrom have zero production callers — declared on the interface, implemented on PrefixSumHeightIndex, exercised only by unit tests. FrameLayout's invalidation surface is (rowCount, rowHeight), and a change in either throws the whole index away rather than invalidating a suffix, so invalidateFrom is not reachable even in principle from the current design. RenderBackend.applyState is likewise an empty method on both backends.

This is a deliberate bet on S5 and S4, and the comments say so. It is listed here because a bet has a due date: if S5 arrives and variable row heights still rebuild the whole index, the interface method should go rather than stay as permanent decoration.

§9-F Options exist that no public path can reach

api/gantt.ts · layout/viewport/viewport.ts

ViewportOptions.overscan is a documented, live-reconfigurable knob with a notify-iff-changed setter. GanttShellOptions does not carry it and GanttOptions does not either, so no consumer can set it and no consumer can reach the Viewport to set it afterwards. The same gap covers everything on Viewport: a consumer can only call panTo if it constructed the ScrollModel itself and kept the reference.

Secondly, GanttOptions and GanttShellOptions are field-for-field identical, and Gantt's constructor re-spreads the two optionals to satisfy exactOptionalPropertyTypes. Adding one key means editing two interfaces, one spread and one barrel — four places for a change that has one meaning.

§9-G hitTest(x, y) does not say which coordinate space

render/backend.ts · render/dom/index.ts

The seam declares hitTest(x: number, y: number) with no note on the frame of reference. The DOM implementation passes them straight to document.elementFromPoint, which takes client (viewport) coordinates — while everything else the backend consumes, GeometryFrame included, is in content coordinates offset by rowLabelWidth and the scroll position. Two spaces, one signature, nothing stating which.

Nothing calls it yet, so nothing is wrong today. S4's gesture controllers are the first callers, and this is precisely the kind of ambiguity that produces an off-by-scroll-offset bug that only shows up once the chart is scrolled. The fix is a named parameter type (ClientPoint vs the existing Point) rather than a comment.

§9-H Two error vocabularies on the public path

view/gantt-shell.ts resolveContainer()

model/errors.ts exists precisely so a public failure carries a stable code, and Viewport.bind uses it (FreeGanttError('viewport-already-bound')). But the most likely error a consumer will ever hit — a container selector matching nothing — throws a bare new Error(...). A consumer cannot branch on it without matching the message string. Two lines to fix, and it should be fixed before anything else starts throwing.

§9-I Barrel laundering, and one seam with no injection point

layout/index.ts · view/index.ts · api/index.ts · time/index.ts · view/gantt-shell.ts

TimeScaleModel is reachable as layout/viewport/time-scale-model.ts, layout/index.ts, view/index.ts and api/index.ts — four paths to one symbol. api/index.ts's own comment records that laundering dayPreset through layout and view was the bug worth fixing, and it was fixed there; layout/index.ts and view/index.ts still launder the models. Separately, time/index.ts omits addMonths, addYears and SUPPORTED_TIME_UNITS, which zone.ts exports — so the barrel is not a complete view of its own layer.

The same shape shows up in GanttShell: RenderBackend<TSurface> is a proper seam with two implementations, and the constructor hardcodes createDomBackend(). There is no way to build a Gantt on the null backend, so the one configuration that would let the whole view/+layout/ stack be tested without a DOM is unreachable from the public path.

§9-J The input reader validates strings hard and numbers not at all

time/input.ts toInstant()

fromPlainString goes to real trouble over a bad string: because Temporal constrains an out-of-range field rather than throwing, it resolves the value and then reads it back, so '2026-02-31' is caught sliding to Feb 28 and becomes an InvalidInstantError. That is careful work, and right.

A number gets one check — Number.isFinite — and is then taken as epoch milliseconds. So start: 20260901, a compact date integer of the kind that arrives from CSVs and older APIs, is read silently as 1970-08-23 and draws a bar half a century off. The string path rejects a date the calendar does not have; the numeric path accepts a value no calendar produced.

Nothing is provably wrong here — epoch ms genuinely is the contract, and any plausibility window (say, rejecting values outside 1970–2400) is a policy choice with its own edge cases. This is listed so the asymmetry is a decision rather than an oversight: either accept it and say so in InstantInput's docstring, or add the guard. It should be settled before S2 makes the same reader run on every mutation.

Explicitly not smells

  • ScrollModel.max being the loosest bound across bindings — so a single chart's panTo can be clamped by another chart's taller content. Deliberate (D-S1.5-1): the model owns one shared position and each Gantt clamps locally; the shorter chart pinning at its last row is the designed fallback.
  • computeFrame's allocating default parameter — it exists so tests and one-shot geometry callers need no index at all, and it is documented as such.
  • The empty BandGeom — an always-equal geom means syncKeyed patches a band node once, at creation, and never again. That is the intended effect, not an oversight; bands gain real geometry in S1.9.
  • Three copies of pane width (Viewport's #paneSize, TimeScaleModel's copy.paneWidth, ScrollModel's copy.pane) — copy-at-bind is the mechanism that stops a caller mutating a shared model's inputs behind its back. The duplication is the price of sharing.

Rules for the content

  1. Read the file, do not infer it. Every claim on this page should be traceable to a line you actually read in this session.   2. Measure the claims that are measurable. §9-A says "two layout passes" because it was counted, not reasoned. If you assert a count, a complexity, or a firing order, prove it and write the number down. If you cannot prove it, write "appears to" and say why you could not.
  3. A smell needs a failure condition, not a preference. Every entry in §9 names the file, the exact circumstance under which it becomes a bug, and what closing it would take.   4. Keep "explicitly not smells" alive. That list exists so the next reader does not re-report a deliberate decision as a defect. When you consider something and decide it is fine, add it there with the reason.

Mechanics of the page itself

  • Standalone HTML, no build step, no external requests. It opens from the filesystem and is served by pnpm dev alongside harness/index.html. Keep it that way: no CDN scripts, no web fonts, no fetches.

Recipe: re-measuring the §9-A pass count

The claim is that construction costs two computeFrame calls and a no-op render costs one. To re-verify after touching render(), Viewport or ScrollModel, drop this at test/dom/tmp-render-count.test.ts, run it, read the numbers, and delete the file — it is a probe, not a test to commit:

import { GanttShell } from '../../src/view/gantt-shell.js';
import { FrameLayout } from '../../src/layout/index.js';
import { entryId } from '../../src/model/index.js';
import type { Entry, Instant } from '../../src/model/index.js';

class FakeResizeObserver {
  constructor(_cb: ResizeObserverCallback) {}
  observe(): void {}
  unobserve(): void {}
  disconnect(): void {}
}
vi.stubGlobal('ResizeObserver', FakeResizeObserver);

const entries: Entry[] = [
  {
    id: entryId('t1'),
    name: 'Entry 1',
    start: Date.parse('2026-09-01T00:00:00Z') as Instant,
    end: Date.parse('2026-09-03T00:00:00Z') as Instant,
  },
];

describe('render count', () => {
  it('counts computeFrame calls', () => {
    const spy = vi.spyOn(FrameLayout.prototype, 'computeFrame');
    const container = document.createElement('div');
    document.body.append(container);
    const shell = new GanttShell({ container, dataset: { entries, timeZone: 'UTC' } });
    console.log('ON_CONSTRUCT =', spy.mock.calls.length);      // expect 2
    spy.mockClear();

    console.log('PER_NOOP_RENDER =', spy.mock.calls.length);   // expect 1
    expect(true).toBe(true);
  });
});
