Who may import whom

.dependency-cruiser.cjs transcribes the diagram literally: one forbid() rule per layer, listing its only legal targets. Anything not listed fails the build (invariant I1).

scheduling time, model Stub. Never imported by data/ statically — they meet at the extension hook.

The five custom lint rules. eslint/rules/ holds what dependency-cruiser cannot see, all scoped to src/**: no-date-outside-time, no-magic-time-constants, no-instant-arithmetic (I10 — time/ is the only place Date.now(), 86400000, or a - b on two Instants is legal), no-time-to-pixel-math and no-scroll-outside-scroll-model (I12 — view/scroll-attachment.ts is the single exempted file). Each rule ships a violation fixture under test/fixtures/ so the rule itself is proven to bite.

3Construction: the call sequence

new Gantt({ container, dataset }) forwards into one long GanttShell constructor. Everything below happens synchronously, in this order, before that constructor returns. Beyond the diagram's steps, the shell now also builds the capability resolver, the gesture pipeline, the collapse state, and the keyboard and wheel navigation attachments.

Why the order is what it is

step the constraint that forces this position
4 Styles and panes before paint. ensureBaseStyles must run before PaneLayout inserts classed elements, or the first frame is unstyled. mount needs the grid and timeline panes that PaneLayout builds.
7–8 Mount before bind. Each model's bind notifies the newcomer at once. Those calls are dropped while wiring, but the render target must already exist for the deliberate first flush() at step 19.
9 Before bind, so #scrollAttachment is never undefined during a render. The timeline pane is the single native scroller.
10–12 bind() always notifies the newcomer, once per sub-model, with no Viewport batch around the pair. Those two onChanges land before #viewportHandle is assigned. #phase drops them so they do not request() a frame. The first real frame is step 19.
14–15 One synchronous measurement, because a real ResizeObserver's first callback is queued, not immediate. The size is the timeline pane's own box — the grid pane never overlapped it, so nothing is subtracted. --fg-row-height is re-read here, not per render.
17–18 Capabilities and gestures after the viewport. The gesture pipeline needs the viewport's scale for draft math, and the capability resolver needs the consumer's interactions options which the shell has by then. Keyboard and wheel navigation sit at the end so the elements they attach to exist.

The pipeline inside computeFrame

The layout pass is no longer a flat row-per-entry walk. Between input and culling it now resolves rows from a row source, produces items per EntryKind, and packs overlaps into lanes:

  1. resolveRows turns the configured rowSource (entries, group, custom) into an ordered list of rows, each stamped with a sequential index (resolve-rows.ts).
  2. produceItems maps each row's entries to Items by EntryKind — a span yields segments or one bar, a group yields a bracket, a milestone yields a diamond (items/produce-items.ts).
  3. packLanes greedy first-fit packs each row's items into lanes so overlapping bars do not collide when heightMode: 'pack' (lanes/pack-lanes.ts).
  4. Cull then trims to the visible window, and header/date-line emission closes the pass.

The two coordinate rules computeFrame keeps

  • Windowed vs. full. rows and items hold only what survived culling; contentWidth/contentHeight are always the full extent. That split is what lets the scroll model compute a real maximum from a frame that drew twelve rows out of two thousand.
  • Zero disables culling. A zero visible.height means "no culling at all", not "an empty window" — and likewise for width. Without that rule an unmeasured container (detached, display:none, pre-paint) would silently render nothing.
  • Overscan is in index space vertically, pixels horizontally. Vertical overscan counts rows and goes through the height index, so it stays correct as row heights vary with packing. Horizontal has no rows to count, so it is a pixel buffer.
  • Rows are culled vertically only. A row whose item is off-screen horizontally is still emitted — the grid pane needs its label.

5The notification machine

Four classes, layered, each one strictly smaller than the one above. This is the most intricate part of the codebase and the part most worth understanding before changing anything in layout/viewport/.

derived from layout/viewport/batched-notifier.ts, bound-value.ts, time-scale-model.ts, scroll-model.ts, viewport.ts

The one contract everything here implements (D-S1.5-4): bind always notifies the newcomer; every other notification fires if and only if the resolved value actually changed. A newcomer's notification is its first render, so it does not wait for an open batch. A departing binding is never notified of its own departure; the survivors are, if the value moved without it.

The four layers, smallest first

class knows about deliberately does not know about
BatchedNotifier a depth counter, a pending flag, one deliver callback bindings, values, what "changed" means. It is the whole batching mechanism and nothing else.
BoundValue<B,V> the binding set, the memoized resolved value, the last-notified value, and the notify-iff-changed rule time, scroll, pixels. It takes resolve and equals as a contract and has no opinion on either.
TimeScaleModel / ScrollModel what to resolve from a binding set, and what counts as a change each other, and the DOM. They differ only in those two functions.
Viewport one Gantt's pane size, content size and overscan; fans both models into one reaction how either model resolves anything. It uses BatchedNotifier alone — it has one subscriber and no value of its own to compare, so BoundValue's comparison half would be a capability it must not have.

Where the batches nest

Viewport.batch(run)
  └─ Viewport.#notifications.batch(          // coalesce the consumer reaction
       scale.batch(                          // coalesce within TimeScaleModel
         scroll.batch(run)))                 // coalesce within ScrollModel

Viewport.setPaneSize(size)                   // one measurement, two models
  └─ #notifications.batch(() => {
       scaleHandle.setPaneWidth(size.width)  // may notify
       scrollHandle.setPaneSize(size)        // may notify
     })                                      // → at most ONE render()

Without Viewport's own batching layer, a single resize would deliver two notifications for one caller-visible change: the two models dedupe within themselves, but neither knows the other was touched by the same call.

The time pipeline

Everything that turns a date into a pixel goes left to right through here. Nothing outside time/ is allowed to shortcut it.

Ten files, all types, plus three id helpers and the FreeGanttError family. That is the entire runtime — the layer exists so layout/, data/, render/ and view/ share one vocabulary without depending on each other.

type shape the rule it encodes
Instant number & {__brand} Epoch ms. Branded so a naked number cannot be passed as a date by accident.
TimeSpan { start, end } Half-open [start, end) in storage. Display is inclusive, via one formatting helper — never an inline end - 1.
EntryId / RowId / ItemId string & {__brand} Three distinct brands over string, so a row id cannot be used where an item id belongs.

derived from a full read of src/**; re-verified 2026-08-31 against the S4 tree

§9-B Boot ordering is held by a boolean, not by structure

view/gantt-shell.ts #wiring — now #phase

The invariant is "no render happens until backend, scroll, viewport and the first pane measurement are all wired". It is enforced by one field that guards the length of the constructor. It is now named #phase rather than #wiring — it says which phase it guards — but it is still a flag: reordering two constructor statements would produce a render against a half-built shell, or a dropped first render, with nothing failing loudly. Premature bind() notifies now hit FrameScheduler.request() rather than render() directly, so the flag's job is smaller than it was, but it is still what drops those two calls.

The structural fix is the usual one — a private #wire() that returns the fully-built collaborators, with render() unreachable until it has returned — but it is worth doing only when a later slice adds a fourth thing to wire, not before. Partially addressed in S3 (the flag now guards a phase rather than a boolean state), still open structurally.

§9-E Interfaces written ahead of their only consumer

layout/row-height-index.ts · layout/frame-layout.ts · render/backend.ts

RowHeightIndex.heightAt and RowHeightIndex.invalidateFrom have zero production callers — declared on the interface, implemented on PrefixSumHeightIndex, exercised only by unit tests. FrameLayout's invalidation surface is (rowCount, rowHeight), and a change in either throws the whole index away rather than invalidating a suffix, so invalidateFrom is not reachable even in principle from the current design. RenderBackend.applyState is likewise an empty method on both backends.

This was a deliberate bet on S5 — and S5 arrived with lane packing, which exercises a different kind of row-height variability (per-row pack height) than suffix invalidation. The bet is still open: if a later slice needs variable row heights, the interface method should go rather than stay as permanent decoration.

§9-G hitTest(x, y) does not say which coordinate space

render/backend.ts · render/dom/index.ts

The seam declares hitTest(x: number, y: number) with no note on the frame of reference. The DOM implementation passes them straight to document.elementFromPoint, which takes client (viewport) coordinates — while everything else the backend consumes, GeometryFrame included, is in content coordinates offset by the timeline pane's scroll position. Two spaces, one signature, nothing stating which.

This was predicted to bite in S4 — and S4's GesturePipeline is now a real caller, so the ambiguity has a live victim. So far the pipeline converts to content coordinates before calling back, avoiding the bug, but the seam still does not state the space it means. The fix is a named parameter type (ClientPoint vs the existing Point) rather than a comment. Now actively the nearest-to-bite finding.

§9-I Barrel laundering, and one seam with no injection point

layout/index.ts · view/index.ts · api/index.ts · time/index.ts · view/gantt-shell.ts

Resolved (issue #91): TimeScaleModel is no longer reachable through four paths. api/index.ts imports it straight from layout/index.ts and view/index.ts dropped the re-export. time/index.ts now exports what zone.ts always had.

Still open: the null backend is RenderBackend<void>, a different THost from the shell's HTMLElement, so it still cannot be swapped in via GanttShellOptions.backend; PaneLayout mounts real HTMLElements regardless of which backend paints them, so driving the whole view/+layout/ stack DOM-free needs a change there too. The hardcoded-call-site half is closed; the DOM-free-testing half is not.

Explicitly not smells

  • ScrollModel.max being the loosest bound across bindings — so a single chart's panTo can be clamped by another chart's taller content. Deliberate (D-S1.5-1): the model owns one shared position and each Gantt clamps locally; the shorter chart pinning at its last row is the designed fallback.
  • computeFrame's allocating default parameter — it exists so tests and one-shot geometry callers need no index at all, and it is documented as such.
  • The empty BandGeom — an always-equal geom means syncKeyed patches a band node once, at creation, and never again.
  • Three copies of pane width (Viewport's #paneSize, TimeScaleModel's copy.paneWidth, ScrollModel's copy.pane) — copy-at-bind is the mechanism that stops a caller mutating a shared model's inputs behind its back. The duplication is the price of sharing.
  • A numeric InstantInput is epoch milliseconds — the string path rejects calendar-impossible dates; the numeric path only checks Number.isFinite. Deliberate: InstantInput's docstring states the contract, so a compact date integer such as 20260901 is still a silent 1970 date, not an oversight.
  • overscan not on public GanttOptions — live on GanttShell/Viewport; withheld from the app-author surface (issue #84). Pan goes through panToDate/panToNow, not a raw ScrollModel.panTo.
  • interaction/ never importing scheduling/ — the gesture layer drives gestures and nothing else; scheduling enters only through data/'s extension hook in S7. That boundary is deliberate and is not to be crossed by editing interaction/ to reach the engine.
