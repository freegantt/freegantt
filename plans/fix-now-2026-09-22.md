## 4. The issues

### 4.1 #400 — the package installs with its build (lane A)

**Now.** The version is `0.1.0`, and `prepare` only sets the hooks path. `prepublishOnly` builds, but
a git dependency and a plain `pnpm pack` never run it. So the tarball has no `dist/`.

**Steps**

1. Add a `prepack` script that runs the library build: `vite build --config vite.lib.config.ts`.
   - Do not call `scripts/check-lib-build.mjs` from `prepack`. That script runs
     `pnpm pack --dry-run`, which runs `prepack` again. That is a loop.
   - Delete `prepublishOnly`, because a publish runs `prepack` too. Keep the check in `pnpm build`.
2. Prove the git-dependency path by experiment, not by reading docs. In a scratch project, install
   from a local clone (`git+file://…#<sha>`) with pnpm and with npm. Check that `dist/api/index.js`
   arrives.
   - If `prepack` is not enough, stop. Ask the owner the #400 question in §2. Do not add a build to
     `prepare` without that answer.
3. Add `scripts/check-pack-install.mjs`:
   1. `pnpm pack` into a temp folder.
   2. Make a scratch project and install the tarball and `typescript`.
   3. Compile `import { Gantt } from 'freegantt'` under `strict`. It must pass.
   4. Compile `import … from 'freegantt/src/api/index.js'`. It must fail to resolve (I11).
   5. Delete the temp folder.
4. Add the script to `verify:full`, which CI runs (`.github/workflows/ci.yml:111`). Then CI cannot
   miss a broken tarball again.
5. Tick the parts of R5 that pass in `plans/03-slices.md` §S6 and `plans/s6-scale-and-sync/README.md`
   §1. "Bundle within budget" stays open until #342 is decided.

**Out of scope:** `publishConfig`, the release workflow and the version policy. They go to #442.

**Done when**

- A clean-clone `pnpm pack` holds `dist/api/index.js` and `dist/api/index.d.ts`.
- A git install from a local clone works with pnpm and with npm.
- The scratch import compiles, and the `freegantt/src/...` import fails.
- `pnpm install` in a fresh clone still sets `core.hooksPath` to `.githooks`.
- `verify:full` runs `check-pack-install.mjs` and passes.

### 4.3 #414, part one — no per-frame Map of every Entry (lane B)

**Now.** `placeFrame` runs `new Map(input.entries.map(…))` on every frame (`src/layout/frame.ts:545`).
A scroll changes no Entry, so this allocation is wasted work in proportion to the dataset (I5).

**Steps**

1. Read where `input.entries` comes from. `GanttShell.render()` passes `dataset.entries.all`
   (`src/view/gantt-shell.ts:2506`), which reads `#allLive()` in `src/data/entry-store.ts:338`. Find
   out if that getter returns the same array from frame to frame when nothing is committed.
2. Keep the map in `FrameMemory` (`src/layout/frame-memory.ts`). Rebuild it only when its input
   changes.
   - Key the cache on the `entries` array itself, not on `datasetRevision` alone. Find out first how
     a drag preview reaches `placeFrame`. If a preview can change what a frame paints while the
     revision stays the same, a revision key paints stale values.
   - If the array is new on every frame, fix that upstream first. Then this cache can hit.
3. Add a test: two frames with the same entries share one map. Add a second test: a frame after a
   commit, and a frame during a drag preview, both paint the new values.
4. Run `pnpm measure:scale` at 10k before and after. Put both numbers in the pull request.

**Out of scope:** the row-plan cache (#414 questions 1 and 2). It waits for the ruling in §2.
Keep #414 open.

### 4.6 #429 — the hierarchy page updates its row source the documented way (lane C)

**Now.** `buildRowSource()` (`harness/hierarchy.ts:110-135`) rebuilds the whole source from the
`<select>` controls on each change. `docs/07-row-source-updates.md:156-161` has to warn readers not
to copy it. The harness is the library's first example, so it must show the right pattern.

**Steps**

1. Copy the shape of `harness/main.ts:166-172`. A sort or filter change reads `gantt.rowSource` and
   spreads one key into it. Only a change of `source` (tree, flat or grouped) builds a new source.
2. Keep one literal for the first mount in `mountGantt`.
3. Delete the caveat in `docs/07`, and say that both pages use the pattern.
4. If the new shape needs a read that `Gantt` does not give, stop. Report the API gap (Stop rule).

**Done when:** no handler in `harness/hierarchy.ts` rebuilds a source that it could spread, the
hierarchy e2e spec passes, and a human pokes the page (sort, filter, group, collapse).
