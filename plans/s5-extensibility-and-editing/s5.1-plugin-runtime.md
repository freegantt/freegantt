# S5.1 — The plugin runtime

**Slice:** S5 · **Step:** 1 of 12 · **Spec:** [`README.md`](./README.md) · **Decisions:** D-S5-1 … D-S5-5
**Prerequisite:** S4 gate green · **Ends with:** `plugins: [logEverything()]` sets up on mount, disposes on `destroy()`, and a private import inside `extensions/` fails the build.

## 1. Decisions

### D-S5-1 — Two contracts, two hosts

`GanttPlugin` installs on a `Gantt`. It sees the DOM seams and lives as long as that Gantt.
`DatasetPlugin` installs on a `Dataset`. It is DOM-free, and it owns the extension hook and per-plugin storage (S5.10).

```ts
// model/plugin.ts — types only, per the model/ rule
export type PluginId = string;
export type Disposer = () => void;

export interface GanttPlugin {
  id: PluginId;
  /** Called once, after the Gantt mounts. Returns a disposer for the plugin's own resources. */
  setup(ctx: PluginContext): Disposer;
}
```

One merged contract cannot work: a headless `Dataset` in Node must run a scheduling plugin with no Gantt in the process (D4), and a Gantt plugin must never reach the extender slot, whose whole contract is one occupant at a time (D-S2-6). Two hosts state that in the type system instead of in a comment.

`extensions/` runs both hosts. `DatasetPlugin`'s host is DOM-free by its own imports, which is why it may live in a DOM-touching layer without breaking anything (the `ItemProducer` precedent, ADR 0002: pure code registered through a DOM-side host).

### D-S5-2 — `plugins: [factory()]`, not `features: { name: true }`

`plans/02` §2 sketched `features: { tooltips: true, contextMenu: {...} }`. That shape cannot pass `[S5-A6]`: a name-keyed table forces the `Gantt` to import every built-in it can name, so an unused feature still ships. A factory the consumer imports is tree-shakeable by construction.

```ts
new Gantt({ container, dataset, plugins: [tooltips(), contextMenu({ items })] });
```

Read the call site aloud: "new Gantt with plugins tooltips and context menu." Options that a feature used to take are now that factory's arguments, which also removes the question of where a feature's config lives.

`plans/01` §10's "Plugins are configured declaratively (`features: …`) and are tree-shakeable" keeps its second half and loses its first. Spec edit, this step.

### D-S5-3 — `plugins` is live; `id` is identity; disposal is reverse order

Every config key is live (`plans/02` §2), and `plugins` is a config key.

```ts
gantt.plugins = [...gantt.plugins, myPlugin()];   // sets up the new one only
gantt.plugins = gantt.plugins.filter((p) => p.id !== 'demo.lock');  // disposes that one only
```

Assignment diffs by `id`: a plugin whose `id` is in both lists is left alone and is **not** re-set-up, even if the value is a new object. This is what stops a re-render loop when a consumer rebuilds the array inline. Two plugins with one `id` in one list is `DuplicatePluginIdError` at assignment.

`gantt.destroy()` disposes plugins first, then panes — a plugin's disposer may still need its overlay node. Disposal runs in reverse registration order, so a plugin that registered over another one unwinds first.

### D-S5-4 — Registration is legal during `setup` only

Every `ctx.*.register*` call is legal while `setup` runs and throws `RegistrationClosedError` afterwards.

Two reasons. A Field must be declared before the first Rollup (S5.9, D-S5-21). And one resolution per seam is what makes renderer and keymap conflicts detectable at install time instead of at the first paint. A plugin that wants to change behaviour later changes it through the public API, exactly as a consumer does.

### D-S5-5 — `extensions/` imports `api/` and `model/` only

The dogfood gate is a lint rule, not a review note.

```js
// .dependency-cruiser.cjs
{
  name: 'extensions-public-only',
  severity: 'error',
  from: { path: '^src/extensions' },
  to: { path: '^src/(?!extensions|api|model)' },
}
```

Built-ins live in `src/extensions/features/`, so they can only reach what a third party reaches. When a built-in cannot do its job, the public API has a gap: close the gap, never widen the rule. `scripts/guard-red-test.mjs` gains the matching red test — a temporary `import '../view/styles.js'` inside `extensions/` must fail the build.

The runtime itself (`extensions/plugin-host.ts`) is under the same rule. `view/gantt-shell.ts` constructs the host and hands it the public `Gantt` façade — the direction of the arrow is `view/` → `extensions/`, never back.

### The context this step ships

```ts
export interface PluginContext {
  /** The public Dataset. No privileged access, no second surface. */
  dataset: Dataset;
  /** The public Gantt, for reading live config and calling public methods. */
  gantt: Gantt;
  events: GanttEvents;          // on/off over GanttEventMap, including cancelable before*
  commands: CommandRegistry;    // S5.2
  view: {
    registerDecoration(layer: DecorationLayer, provider: DecorationProvider): void;   // S5.6
    registerGridColumn(column: GridColumn): void;                                     // S5.7
    registerRenderer(point: RendererPoint, renderer: Renderer): void;                 // S5.4
    overlay: OverlayHost;                                                             // S5.3
  };
  layout: {
    registerItemProducer(kind: EntryKind, producer: ItemProducer): void;              // S5.9
  };
  interaction: {
    registerKindDefaults(kind: EntryKind, defaults: KindDefaults): void;              // S5.9
    registerKeybinding(binding: KeyBinding): void;                                    // S5.2
  };
  disposables: DisposableStore;
}
```

S5.1 ships the host, the shape, `disposables`, and the `events` member. Every other member arrives in the step named beside it, with the code that honours it (I11) — a `register*` that does nothing is exactly the dishonest surface `no-not-implemented` catches. The context object is built by the host, one member per seam, from the shell's wiring list.

## 3. Tests

- `src/extensions/plugin-host.test.ts` — setup runs once per plugin, in list order; a disposer runs on removal; assigning a list with the same ids sets nothing up again; a duplicate id throws `DuplicatePluginIdError`; a `register*` after `setup` throws `RegistrationClosedError`
- `src/extensions/disposables.test.ts` — disposal is reverse order and idempotent
- `src/api/gantt.test.ts` — `plugins` assignment adds and removes without a remount (bar nodes keep identity, I8); `destroy()` disposes plugins before panes; two Gantts install independent plugin instances (I2)
- `node scripts/guard-red-test.mjs` — a private import inside `extensions/` fails `depcruise`
