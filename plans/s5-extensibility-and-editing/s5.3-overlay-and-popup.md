# S5.3 — The overlay host and the Popup primitive

**Slice:** S5 · **Step:** 3 of 12 · **Spec:** [`README.md`](./README.md) · **Decisions:** D-S5-8, D-S5-9
**Prerequisite:** S5.1 · **Ends with:** a popup anchored to a bar, flipped at the pane edge, clamped inside the container, and focus returned to the invoker on close.

## 1. Decisions

### D-S5-8 — The host is `view/`'s place; the popup is `extensions/`'s thing

`OverlayHost` is a layer of the Gantt, like a pane. It owns one absolutely positioned element over the container, its stacking order, and its lifetime. It knows nothing about tooltips or menus.

```ts
// view/overlay-host.ts
export interface OverlayHost {
  /** Mounts `content` in the overlay layer and returns a handle that removes it. */
  present(content: HTMLElement): OverlayHandle;
  /** The container's own client rect — the outer clamp, so a popup never spills past the Gantt entirely. */
  readonly bounds: DOMRect;
  /**
   * The grid pane's and timeline pane's own client rects (issue #137 F8). The container
   * spans both panes, so `bounds` alone cannot flip a popup at a pane edge — a tooltip
   * clamped only to `bounds` would overlap the grid pane instead of flipping inside the
   * timeline pane, contradicting the "flips at the pane edge" acceptance line (README U5,
   * this step's own end-state). Placement flips and clamps against the anchor's own pane
   * rect; `bounds` remains the outer clamp for a popup whose anchor is not inside either
   * pane (a toolbar button, say).
   */
  readonly paneBounds: { grid: DOMRect; timeline: DOMRect };
}
```

`Popup` is the anchoring, flipping, clamping and dismissal primitive built on that host. It lives in `extensions/popup.ts` because its only callers are plugins, and because building it there proves a third party can build the same thing.

```ts
// extensions/popup.ts
export interface PopupOptions {
  anchor: Anchor;                      // a client rect, or an element to read one from
  placement?: PopupPlacement;          // 'top' | 'bottom' | 'start' | 'end'; default 'bottom'
  focus?: 'trap' | 'none';             // default 'none'
  dismissOn?: readonly DismissTrigger[];  // default ['escape', 'outsidePointer', 'scroll']
  content: ElementDescription;         // S5.4 — plain data, applied by the reconciler
}

export interface Popup {
  open(options: PopupOptions): void;
  close(): void;
  readonly isOpen: boolean;
}
```

One implementation serves the tooltip, the context menu and the cell editor. Three positioners would be three sets of edge-case bugs.

Placement is: try the requested side; if the box does not fit inside the anchor's pane rect (`paneBounds.grid` or `paneBounds.timeline`, whichever pane the anchor is in — `bounds` for an anchor outside both), flip to the opposite side; then clamp along the cross axis so the box stays inside that same rect. No third pass, and no auto-repositioning loop — a popup that no longer fits after a scroll dismisses instead (below), which is what the `dismissOn` default already says.

### D-S5-9 — Focus policy is declared per popup, not decided per caller

`focus: 'none'` (the default) never moves focus. The tooltip uses it: a hover affordance that steals focus from the bar is a bug, and a keyboard user reads the same text from the bar's own description instead (S5.11).

`focus: 'trap'` moves focus to the first focusable node inside, keeps Tab inside the popup, and returns focus to the element that was focused when it opened. The context menu and the cell editor use it.

Dismissal triggers are declared, not hard-coded:

| Trigger | Meaning |
|---|---|
| `escape` | Escape anywhere while the popup is open |
| `outsidePointer` | a pointerdown outside the popup and outside its anchor |
| `scroll` | any scroll of a pane the anchor lives in |
| `blur` | focus leaving the popup (editors, so a click elsewhere commits) |

**Container resize (issue #137 F9).** None of the four triggers above fires on a window resize, so a clamped popup would sit stale — out of bounds, or anchored to a rect that no longer matches the resized container. `Popup` does not need a fifth `dismissOn` trigger for this: the overlay host already measures the container on resize (it has to, to keep `bounds`/`paneBounds` correct), so an open popup repositions — reruns flip/clamp against the fresh rects — on every resize the host observes, the same way it would on the anchor moving. A popup that can no longer fit anywhere reasonable (the anchor itself scrolled out) falls back to the `scroll` trigger's dismissal, not a fifth case.

Escape ordering matters and is stated once here: while a popup is open, Escape closes the popup and stops there. It does not also clear the selection (S3's Escape) — the innermost open thing wins. The keymap resolver (S5.2, D-S5-7) already gives this for free, because the popup registers its Escape binding last and unregisters it on close.

The popup writes its content through the reconciler, not through `innerHTML` (I13). That is why `content` is an `ElementDescription` and not a node, and it is why S5.4 lands before the built-ins that use it.

| File | Job |
|---|---|
| `src/view/overlay-host.ts` | the overlay layer, its bounds, `present`/`OverlayHandle` |
| `src/view/pane-layout.ts` | mounts the overlay layer above both panes |

## 3. Tests

- `src/view/overlay-host.test.ts` (dom) — `present` mounts above both panes; the handle removes the node; `destroy()` clears the layer; `paneBounds` reports the grid and timeline pane rects independently (issue #137 F8)
- `src/extensions/popup.test.ts` (dom) — a popup at the right pane edge flips to `start` inside that pane's own rect, not the container's (issue #137 F8); a tall popup clamps inside its pane's bounds; Escape closes and only closes the popup; an outside pointerdown closes; a scroll closes; `focus: 'trap'` cycles Tab and restores focus on close; `focus: 'none'` never moves focus; a container resize repositions an open popup against the fresh rects (issue #137 F9)
- `src/render/dom/index.test.ts` (dom) — popup content is applied through the reconciler; a `text` value with markup in it stays text (I13)
