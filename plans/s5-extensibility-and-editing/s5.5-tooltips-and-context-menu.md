# S5.5 — Tooltips and the context menu, as plugins

**Slice:** S5 · **Step:** 5 of 12 · **Spec:** [`README.md`](./README.md) · **Decisions:** D-S5-13, D-S5-14 · **Proves:** `[S5-A1]` — the dogfood gate
**Prerequisite:** S5.2, S5.3, S5.4 · **Ends with:** two shipped plugins, both written against the public contract only, both proven by lint rather than by review.

## 1. Decisions

### D-S5-13 — Built-ins are ordinary plugins in `extensions/features/`

```ts
import { tooltips, contextMenu } from 'freegantt';

new Gantt({ container, dataset, plugins: [tooltips(), contextMenu({ items })] });
```

Each is a factory returning a `GanttPlugin`. Each lives under `src/extensions/features/`, which the `extensions-public-only` rule (D-S5-5) already confines to `api/` and `model/`. That rule is `[S5-A1]`: "zero private imports, lint-proven". A back door cannot be added without failing the build, so nobody has to remember the promise.

Expect this step to find API gaps. That is its job. Each gap gets closed in `src/api/` or in `PluginContext`, with a note in this file's §5, never worked around inside the feature.

**Tooltips.** Hover a bar (or focus it) and a popup shows the entry's name, its dates, and any column marked `tooltip: true`. `focus: 'none'` (D-S5-9), so the pointer path never steals focus and the keyboard path reads the same text from the bar's own accessible description instead (S5.11). Content goes through the `tooltip` renderer point (S5.4), so a consumer replaces the body without replacing the behaviour.

```ts
tooltips({ delayMs: 400, placement: 'top' })
```

**Context menu.** Right-click, or `Shift+F10` / the Menu key, opens a menu of the commands whose `when` passes for the target (D-S5-6). `focus: 'trap'`, arrow keys move, Enter runs, Escape closes and returns focus.

### D-S5-14 — Menu items come from commands, filtered by `when`

```ts
export interface MenuItem {
  command: string;                 // an id in the registry
  /** Overrides the command's own label for this menu only. */
  label?: string;
}
export type MenuEntry = MenuItem | { separator: true };

export interface ContextMenuOptions {
  items?(ctx: { entry?: Entry; defaults: readonly MenuEntry[] }): readonly MenuEntry[];
}
```

`defaults` is `commands.available(ctx)` mapped to items, in registration order. The consumer's `items` returns the final list, so it can append, remove, reorder or replace — the shape `plans/02` §2 already published.

An item names a command and nothing else. It carries no `run` of its own, because then the same action would exist twice: once for the mouse and once for the keyboard, drifting apart at the first change. This is the rule that makes `[S5-A4]`'s keyboard parity cheap.

An item whose command's `when` fails is not rendered. There is no disabled state in S5: a menu of greyed items is a design question no consumer has asked, and hiding is what `when` already means for the keybinding path.

## 3. Tests

- `src/extensions/features/tooltips.test.ts` (dom) — appears after the delay, not before; follows the hovered bar; hides on pointer-out and on scroll; never moves focus; a `tooltipRenderer` replaces the body
- `src/extensions/features/context-menu.test.ts` (dom) — right-click opens at the pointer; `Shift+F10` opens at the focused row; only commands whose `when` passes appear; `items` can append and reorder; Enter runs the command; Escape closes and restores focus
- `src/extensions/plugin-host.test.ts` — removing either plugin from `gantt.plugins` removes its listeners and its overlay content
- `depcruise` — `extensions-public-only` stays green with both features present (`[S5-A1]`)
