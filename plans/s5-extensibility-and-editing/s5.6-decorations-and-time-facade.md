# S5.6 — Decorations and the zone-bound time façade

**Slice:** S5 · **Step:** 6 of 12 · **Spec:** [`README.md`](./README.md) · **Decisions:** D-S5-15, D-S5-16 · **Proves:** `[S5-A2]`
**Prerequisite:** S5.1 · **Ends with:** a weekend-shading plugin in `harness/plugins/`, written against the published types alone, painting bands under the bars.

## 1. Decisions

### D-S5-15 — A decoration provider is pure, and it runs in `layout/`

```ts
export type DecorationLayer = 'underBars' | 'overBars';

export interface DecorationContext {
  /** The visible time span, already widened by overscan. */
  span: TimeSpan;
  /** The rows in that window, so a provider can shade a row instead of a date range. */
  rows: readonly FrameRow[];
  /** Zone-bound date math (D-S5-16). The provider never touches `Date` or a magic constant. */
  time: ZonedTime;
}

export type DecorationProvider = (ctx: DecorationContext) => readonly DecorationInput[];

export type DecorationInput =
  | { kind: 'rangeBand'; start: Instant; end: Instant; class?: string }
  | { kind: 'rowStripe'; rowId: RowId; class?: string };
```

A provider is a pure function of the window. It is registered from the DOM side (`ctx.view.registerDecoration`) and invoked by pure code — the same shape `ItemProducer` already has (ADR 0002's precedent).

Providers speak **time**, not pixels. `layout/` converts through the bound `TimeScale` (I12), which is why `DecorationInput` carries instants and the existing `RangeBand` keeps `x`/`width`. A plugin that computed pixels itself would break the moment the axis is shared (D9).

`RangeBand` and `RowStripe` gain an optional `class`, so two providers' bands are tellable apart in CSS (level 2 of the ladder). The class lands on the decoration node beside `.fg-range-band`; the library never invents one.

Providers run per frame, after rows resolve and before geometry is placed. Their output is memoized on the same key the frame already uses, so a static weekend provider costs one call per window change, not one per render.

### D-S5-16 — `Dataset.time` is the zone-bound façade; `PlainParts` gains `dayOfWeek`

A third-party plugin cannot import `time/` — the `exports` map seals it (`plans/02` §7). Without a public way to ask "which days in this span are Saturdays, in this dataset's zone", `[S5-A2]` is unreachable and every plugin author hand-rolls `86400000`, which is exactly what I10 forbids inside `src/`.

```ts
// The zone is already bound. No caller passes it, and no caller can pass the wrong one.
export interface ZonedTime {
  readonly zone: string;
  startOfDay(at: Instant): Instant;
  startOf(at: Instant, unit: TimeUnit): Instant;
  addDays(at: Instant, days: number): Instant;
  diffDays(a: Instant, b: Instant): number;
  /** 1 = Monday … 7 = Sunday (ISO). */
  dayOfWeek(at: Instant): number;
  /** Each day boundary in `[span.start, span.end)`, ascending. */
  eachDay(span: TimeSpan): readonly Instant[];
  toPlain(at: Instant): PlainParts;
  fromPlain(plain: PlainParts): Instant;
}

dataset.time.eachDay(span).filter((day) => dataset.time.dayOfWeek(day) >= 6);
```

Read the call site: "dataset time, each day of span" and "dataset time, day of week." Both say what they do with the dataset's own zone implied, which is the point of binding it once.

Every method already exists inside `time/zone.ts` except two: `dayOfWeek` (Temporal's `ZonedDateTime` has it; `PlainParts` gains the field) and `eachDay` (a loop over `addDays`, in `time/`, because it is date arithmetic). The façade adds no logic of its own — it binds the zone and forwards. That keeps I10 true: all the math still lives in `time/`.

`ctx.time` inside `DecorationContext` is this same object. A consumer writing `groupBy` or a filter has the same need, which is why it hangs off `Dataset` and not off `PluginContext` alone.

### The gate plugin

`harness/plugins/weekend-shading.ts` is written as if by a third party: it imports from `'freegantt'`, never from a path inside it. `harness/` is outside the `src/**` lint scope by design (CLAUDE.md), so the proof is stronger than a lint rule — the plugin only compiles if the published types are enough. `[S5-A2]`'s e2e test asserts two shaded bands per week in the visible range, and asserts they move when the axis pans.

## 3. Tests

- `src/time/zone.test.ts` — `dayOfWeek` across a DST boundary in a southern-hemisphere zone; `eachDay` returns 7 boundaries for a week and skips nothing on the spring-forward day
- `src/layout/decorations.test.ts` — providers run once per window; output converts through the scale; `class` reaches the decoration; `overBars` and `underBars` stay separate lists
- `src/api/dataset.test.ts` — `dataset.time.zone` is the dataset's zone; a dataset with no `timeZone` binds the resolved one (#129)
