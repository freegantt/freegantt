## 4. Record

Settled by the user, 2026-09-02, across this conversation and the grill comment thread on #111.

- **H1 — take the A/B split, S7-only.** Yes. The code (splitting `plans/01` §7, exporting `Dependency`/`DependencyType`, moving link emission) is S7 work. Only two contract gaps land in S5 — see Gap 1/Gap 2 below.
- **Convenience barrel/default — no silent default; an opt-in helper is fine, once order no longer matters.** No plugin auto-installs another plugin's default instance (considered and rejected — see D-S5-31). Revisiting a **named, opt-in** "install every first-party plugin" helper is tracked separately: [issue #135](https://github.com/Pawel-IT/FreeGantt/issues/135), deferred to S7 once `entryDependencies()` and `scheduling()` exist to bundle.
- **H3 — drop `propagate: false`.** Confirmed. "Arrows, no auto-move" is a plugin swap (install `entryDependencies()` alone), not a flag on the engine.
- **Gap 1 (H4) — cross-plugin store reads are read-only.** Confirmed, landed as **D-S5-30**: `ctx.store.read<T>(pluginId)` returns a `PluginStoreView` (`get`/`all`, no `set`/`remove`); the owning plugin's `reserve()` is still the only write path. §S5.10.
- **Gap 2, revised — order-independence, not order-validation.** The original sketch (declare `requires`, throw `PluginOrderError` on a wrong array order) was superseded: the host **topologically sorts** the installed set by `requires` before running any `setup`, so array position never matters. Only `MissingPluginError` remains. Landed as **D-S5-31**. §S5.10.
- **H2 — naming.** Settled: **`entryDependencies()`**. `precedence()` was the fallback; not needed. `CONTEXT.md` gains a `entryDependencies()` entry, and the **Dependency** and **Scheduling plugin** entries are edited to record the ownership split (§12 spec edit 6, landed with this change).
- **H5 — the record waited for H2.** This entry is that record; it settles with naming decided.
