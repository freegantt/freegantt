## 1. Decisions

### D-S5-28 — The tree-shaking budget is a probe plus a size limit

`[S5-A6]` says unused features are absent from a consumer bundle. Two checks, because either alone lies:

1. **A string probe.** Build a fixture entry that imports `Dataset` and `Gantt` and nothing else. Assert the output contains no marker string from `tooltips`, `contextMenu` or `inlineEditing`. Each built-in carries one distinctive literal for exactly this (its plugin `id`, which it already has).
2. **A size budget.** `size-limit` on two fixtures — core only, and core plus the three built-ins. The gap is the built-ins' real cost, and the core number is the one that must not creep.

The probe catches a feature pulled in by an accidental import. The budget catches slow growth that no probe can see. `plans/04` §2 already budgets `size-limit` for this slice.

D-S5-2's factory shape is what makes both checks pass. If a `features: { tooltips: true }` table had survived, the probe would fail on day one.

### D-S5-29 — The API reference renders the existing API report

`etc/freegantt.api.md` already exists and is already gated by `pnpm api-report` (I11). The docs seed renders that file rather than adding a documentation generator — a dev dependency for something the repo already produces is a cost with no gain.

The gallery is the harness. Each page gains a short explanatory block above the Gantt: what it demonstrates, the config that does it, and a link to the section of `plans/02` that governs it. The pages are the examples a consumer reads first, so `harness/main.ts` and its siblings stay under the same review rule they always were (CLAUDE.md) — code there that re-derives what the library computes is an API gap, and this step is the last chance to catch one before S6.
