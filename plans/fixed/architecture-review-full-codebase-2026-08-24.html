after — one path, one interface

Problem

GanttShell#renderHeader builds tick nodes itself, so the header is invisible to every render adapter — render/null, the declared export seam, can never emit one.

Solution

GeometryFrame grows a header of tick boxes; computeFrame emits it; render/dom reconciles ticks with the reconciler it already runs for bars.

Two documented rules already say this. CONTEXT.md — GeometryFrame is “what a render backend consumes and the only thing it consumes.” CLAUDE.md — “Hot path … zero allocation, never rebuilds a frame”; replaceChildren(...ticks.map(...)) reallocates every tick node on every render.

Wins

  • leverage: sync(frame) covers all rendered state
  • locality: tick geometry sits with bar geometry
  • header tests move from happy-dom to the pure project
  • export seam stops being decorative
  • tick nodes recycle instead of reallocating

Problem

The seam exists, is fully tested, and nothing calls it. The tests guard a module no behaviour depends on, while computeFrame’s inline arithmetic — the code that actually runs — has no variable-height test because it cannot have one.

Solution

Problem

Solution

The second adapter the seam needs: a thin ResizeObserver in view/ pushing measured width into the handle. plans/01 §8.2 D-A already names the file — view/resize-binding.ts, issue #8.

Wins

  • fitProject starts fitting

  • unblocks the S1 split-pane acceptance

5 · bind()’s exceptions are longer than its implementation

Worth exploring in-process

src/layout/viewport/time-scale-model.ts:62–86 · src/view/gantt-shell.ts:40–58

before — shallow: interface ≈ implementation

after — deep: one rule, no exceptions

Problem

Every exception exists to serve one caller’s construction order. The caller is the thing to fix; the model absorbed the workaround instead. Callers must also know bind() retains and writes through the object they passed (binding.viewportWidth = width mutates a live Map key).

Solution

Reorder GanttShell’s constructor: panes and backend first, bind() last. Then bind() notifies uniformly, priorReactions disappears, and the explicit trailing this.render() goes with it.

Stays inside D-A. plans/01 §8.2 locks onChange at bind time and rejects a separate subscribe() — this proposal keeps both, and only removes the exceptions.

Wins

  • interface shrinks by 9 lines of caveat
  • locality: construction order owned by the constructor
  • three notify tests collapse into one rule

Problem

The seam types its host as unknown to stay DOM-free, then every adapter casts it back. The requirement lives in a comment instead of the type, and the cast is unchecked. plans/01 §8.1 specifies mount(host: HTMLElement).

Make the seam generic in its host: RenderBackend<THost>. backend.ts then names no DOM type at all — strictly more DOM-free than today — and each adapter states what it needs.

  • the type states the adapter’s requirement

  • a future canvas adapter is type-checked at the seam

Problem

Two failures of one module. Downward: model/’s types never reach the surface, so nothing legal can construct a Task. Upward: instant, dayPreset and four types are laundered through two barrels with no interest in them, purely to satisfy the layer lint — Shotgun Surgery growing linearly with the surface.

Solution

One module owns the public surface: api/index.ts re-exports model/’s types (the api → model edge both configs already allow) and takes the same type-and-primitive-only edge to time/. The intermediate barrels go back to being internal.

Touches a guard, so it is a spec change. Widening the I1 allow-list needs the human decision the protect-spec hook asks for. The precedent is already in both configs: “model is the type surface api/ re-exports … the layer diagram doesn’t draw the arrow because it’s a type-only re-export, not a behavioral one.”

Wins

  • locality: one file names the public surface
  • two barrels stop carrying foreign symbols
  • AI-navigability: one grep, not four

Top recommendation

Give computeFrame the TimeScale, then move the header band behind the render seam.

One deepening in two steps, and everything else in S1 waits behind it. Layout cannot emit ticks, cull rows, or fill viewport while its only view of the scale is a single function; and until the frame carries the header, view/ keeps rebuilding tick DOM around the seam, where no adapter and no headless test can reach it. Fix the input, and the output follows: GeometryFrame becomes what CONTEXT.md already claims it is — the only thing a backend consumes.

Candidate 3 (wire the height index) is the natural third step: it lands in the same function, and plans/01 §4 already names the index as the source of contentHeight.
