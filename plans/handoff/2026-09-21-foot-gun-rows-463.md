## 4. When to escalate to the parent agent

Stop the subagent and ask the parent when any of these is true. Do not decide these yourself and do not let the subagent decide them.

- **The code disagrees with the issue's evidence.** A `file:line` in the issue no longer says what the issue claims. `docs/agents/review.md`: a plan's account of the code is a claim. Report what you found, then wait.
- **A lint or a boundary blocks the plan as written.** PR 5 is the likely case: `view/` may not import `time/` (I1), and no `Date.now()` or time constant may sit outside `time/` (I10). The issue says the boundary instant comes through the port `panToToday` uses. If that port cannot answer "next tick boundary", ask. Never add an eslint disable to get past it.
- **A harness workaround is tempting.** Any change to `harness/` that works around `src/` is an API gap. Report it; do not tidy it in.
- **A public name or shape the issue did not settle.** The option name on a transaction, a new error field, a new export. The issue settles most of these; anything it leaves open goes to the parent with one recommendation.
- **The gate fails on something your change did not touch.** Report the verdict line and the first failing check. Do not retry blind.
- **`[S1-A12]` fires in PR 5.** `src/api/gantt.test.ts` guards that `--fg-today-line-color` never returns, even as a comment substring. If the timer work trips it, the wording is wrong, not the guard.

Everything else is yours: file placement, test names, the exact sentence of a doc comment inside the issue's meaning, the order of steps inside one PR.
