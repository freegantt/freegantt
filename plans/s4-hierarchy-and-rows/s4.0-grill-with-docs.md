# S4.0 — Grill with docs

**Slice:** S4 · **Step:** 1 of 12 · **Spec:** [`README.md`](./README.md)
**Prerequisite:** none · **Ends with:** an empty grill frontier, answers transcribed to step files, ADRs, and `CONTEXT.md`.

## 1. What this step is

S4 is the largest slice. It owns eleven implementation steps and thirty-four decisions. Before we implement one line of it, we grill the spec.

The grill is a relentless interview. It stresses every settled call. It probes every foot-gun. It finds the silent assumptions.

This step writes no code. It writes understanding.

## 2. How we grill

Run the `grill-with-docs` agent skill over the whole S4 spec. The skill runs two disciplines in one pass:

- `grilling` — work the design tree in rounds. The frontier is every decision whose prerequisites are settled. Ask the whole frontier in one round. Number each question. Give a recommended answer. Wait before the next round.
- `domain-modeling` — record the moment a term or a trade-off resolves. Update `CONTEXT.md` inline. Offer an ADR only for a real trade-off.

Grill the README first, then each step file in order. Scope calls Q1–Q8 are "confirmed", not "settled" — the grill may reopen one if the reasoning does not survive. The decisions index (D-S4-1 – D-S4-34) and the foot-guns table are the spine of the interview.

## 3. Where the answers land

An answer changes the plan, never only the conversation.

- A decision that changes a step's semantics updates that step file and the README's decisions index.
- A blurred term or boundary updates `CONTEXT.md`.
- A hard-to-reverse choice with real alternatives becomes an ADR in `docs/adr/`.

## 4. Exit

The step is done when the frontier is empty. Every branch of the tree is visited. Nothing stays silently assumed. The user confirms the shared understanding.

Do not act on the plan until then.
