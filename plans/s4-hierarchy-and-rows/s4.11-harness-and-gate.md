## 1. Decisions

### D-S4-34 — One harness page, one Gantt, one `rows` switch

`harness/hierarchy.html` + `hierarchy.ts`, linked from the index and from the docs gallery.

**One Gantt.** A button switches `gantt.rows` between the tree and a grouped source. That proves the Row ≠ Entry payoff and live reconfiguration in the same demo. Two Gantts on one Dataset is **not** the demo: D9 is about a shared axis between charts with different data (`plans/02` §5), and ADR 0005 §34 dropped the side-by-side page for this reason.

Toolbar, and what each control proves:

| Control | Proves |
|---|---|
| Rows: Tree / Grouped / Flat | `[S4-A3]` — live re-resolution, scroll survives |
| Height: Fixed / Pack | `[S4-A5]` — lane packing and variable heights |
| Columns: add or remove `cost` | S4.3 — `gridColumns` is live |
| Team filter | `[S4-A7]` — keep-ancestors |
| Sort by Start / Cost / Name | S4.9 — Field-driven sort |
| Expand all / Collapse all | `[S4-A6]` |
| autoGroup on/off + Reparent | `[S4-A9]` |
| Edit cost, Undo, Redo | `[S4-A1]` — rollup and undo |
| Export / Import JSON | `[S4-A1]`'s round-trip half |

The changeset log panel from S2's `data.html` is reused here, because every one of those boxes is easier to believe when the reader sees the rows the edit produced.

**Fixture:** `fixtures/hierarchy-dataset.ts` — three levels deep, one empty `'group'`, one `'milestone'`, one entry with three `segments`, several deliberate overlaps for pack mode, a `cost` in `meta` on every leaf, and a `team` for the filter. Deterministic, no clock read. The page constructs a Dataset; the Rollup is the Dataset default (D-S4-7).

`harness/main.ts` is reviewed on this commit, changed or not (CLAUDE.md). Anything there that restates a library default or re-derives what the library computes is an S4 API gap, and it is closed in `src/`, not tidied in the harness.
