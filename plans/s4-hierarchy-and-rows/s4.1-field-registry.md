# S4.1 — Field registry

**Slice:** S4 · **Step:** 1 of 11 · **Spec:** [`README.md`](./README.md) · **Decisions:** D-S4-1 – D-S4-5, D-S4-35
**Prerequisite:** none · **Ends with:** `dataset.entries.update('t1', { cost: 500 })` commits one changeset row whose `field` is `cost`, and a misspelt key throws.

## 1. Decisions

### D-S4-1 — The types live in `model/`; one registry lives in `data/`, and it holds the whole declaration

`model/field.ts` is types only, like every other `model/` file. `data/fields/field-registry.ts` holds the one `FieldRegistry` a `DatasetState` owns.

```ts
// model/field.ts — types only
export type FieldKey = CoreFieldKey | (string & {});     // moves here from model/change-set.ts
export type AggregatorName = 'min' | 'max' | 'sum' | 'count' | 'none' | (string & {});
export type FieldTypeName = string & {};

export type FieldSource =
  | { from: 'entry'; field: CoreFieldKey }
  | { from: 'meta'; key?: string }                 // key defaults to the Field key
  | { from: 'compute'; read(entry: Entry, ctx: FieldContext): unknown };

export interface Field<TValue = unknown> {
  key: FieldKey;
  type?: FieldTypeName;
  source?: FieldSource;                            // default: { from: 'meta', key: this Field's key }
  rollUp?: AggregatorName;                         // name only, including a consumer Aggregator
  equals?(a: TValue | undefined, b: TValue | undefined): boolean;
  compare?(a: TValue | undefined, b: TValue | undefined): number;  // sort order; default is the stored value
  formatValue?(value: TValue | undefined, ctx: FieldContext): string;
  column?: Omit<GridColumn, 'field'>;
}

/** A `Field` with `key` and `source` omitted — one bundle applied by name to many Fields. */
export type FieldType<TValue = unknown> = Omit<Field<TValue>, 'key' | 'source' | 'type'>;

/** Everything a value needs to be read or rendered as text, and nothing about a view. */
export interface FieldContext {
  readonly timeZone: string;
  readonly locale?: Intl.LocalesArgument;
  read<T>(entry: Entry, key: FieldKey): T | undefined;
  durationOf(entry: Entry): Duration;
}
```

**Omit `source` and the value lives in `meta` under the Field key** — D-S4-35. `{ key: 'cost', type: 'money' }` is the common call.

The registry stores the **whole** declaration, `column` included. `data/` carries that sub-object and never interprets it; `view/` reads it back through the Dataset when it resolves Grid columns (S4.3).

Rejected: two registries, one in `data/` for the data half and one in `view/` for the presentation half, written by `api/`. One declaration stored twice drifts, and `fromJSON` would rebuild only one of them. ADR 0005 §31's "split at `api/`" is about *who sends what where*, and a read-time split satisfies it with one copy.

Rejected: `Dataset<TFields>` generic. ADR 0005 already rejected it — the parameter propagates through `Gantt`, `view/` and `layout/` to serve a boundary concern.

### D-S4-2 — One adapter reads and writes a `FieldSource`

`data/fields/field-access.ts` holds the only `switch` over `FieldSource` in `src/`:

```ts
export function readField(entry: Entry, field: ResolvedField, ctx: FieldContext): unknown;
/** Folds one field write into an entry-shaped `StoredEdit`, merging `meta` rather than replacing it. */
export function writeField(edit: StoredEdit, entry: Entry, field: ResolvedField, value: unknown): StoredEdit;
```

Adding a fourth source variant later changes this file and nothing else (open/closed). Every other layer asks for a value by **Field key** and never learns where it sits — which is what ADR 0005 §24 means by "`meta` is demoted from surface to storage".

**Edits stay entry-shaped inside the store.** `EntryEdit` widens to accept declared keys; `entries.update` folds each declared key through `writeField` before it stages, so `StoredEdit` keeps the shape S3's `layout/gesture-draft.ts` already builds. Nothing in the gesture path changes. A write to a declared meta Field **creates** `meta` when the entry had none — `{ cost: 500 }` on a bare span becomes `entry.meta = { cost: 500 }`. It merges when `meta` already exists. It never replaces the object.

**`diffEdit` becomes Field-aware.** It consults the registry, so:

- `update('t1', { cost: 500 })` emits one row, `field: 'cost'`, `from: 400`, `to: 500`. No `meta` row.
- `update('t1', { meta: {…} })` emits one `meta` row carrying the whole object as authored, **plus** one row per changed declared key. Apply order within one entry is the `meta` row first, then the declared rows. Undo inverts every row and keeps the same order, so it restores exactly.

Rejected: a Field-keyed write set (`ReadonlyMap<EntryId, ReadonlyMap<FieldKey, unknown>>`). It reshapes S2's transaction machinery and S3's gesture drafts for a translation that one function already does.

### D-S4-3 — An Aggregator is always a registered name

Shipped: `min`, `max`, `sum`, `count`, `none`, `weightedMeanByDuration`. `data/fields/aggregators.ts` holds them; `DatasetOptions.aggregators` adds consumer ones by name. An unknown name throws `UnknownAggregatorError` at construction, never at commit time. `weightedMeanByDuration` ships because a consumer Field and S7's Progress Field both need it — it is not attached to a core Field (ADR 0008).

`rollUp` never takes a bare function — a name serializes into a Document and a function does not (ADR 0005). A **Field type** carries `rollUp` as that name. The function lives in `aggregators`. There is no closure on the Field.

**Resolution, then participation.** The registry merges the Field onto its Field type first. The Field's own keys win. After that merge:

- A resolved `rollUp` that names an Aggregator (`'sum'`, `'min'`, a consumer name) participates.
- A resolved `rollUp` of `'none'`, or no `rollUp` left after the merge, does not participate. The parent keeps the value the caller assigned for that Field, even when the parent's Kind is in `rollUpKinds`.

So `{ key: 'cost', type: 'money' }` with `fieldTypes.money.rollUp: 'sum'` and no Field-level `rollUp` sums. The type's `rollUp` may name a consumer Aggregator (`'riskWeighted'`): the name must sit in `aggregators`, the same as a shipped one. `{ … type: 'money', rollUp: 'none' }` opts that Field out: the Field's key wins. `{ key: 'notes' }` with no type and no `rollUp` does not participate.

There is no global default Aggregator. Core does not ship primitive Field types (`number`, `instant`, `text`) with a baked-in `rollUp`. `sum` is the usual default a **consumer** puts on a type such as `money`. It is the wrong default for an Instant: adding start times is not a span. The Span rollup is `start` as `min` and `end` as `max`, set on those core Fields, not a date-flavoured `sum`. A consumer Instant Field that should envelope children declares `rollUp: 'min'` or `'max'` (or a type that carries one of those names). Dataset-level none is `rollUpKinds: 'none'` (D-S4-6), not a second option named `rollUp`.

Shipped Aggregators skip holes (`undefined`, non-numeric for `sum`/`min`/`max`, zero-duration children for the weighted mean) and never throw. If every child is skipped they return `undefined` (keep the stored value). The shipped `'none'` Aggregator always returns `undefined`.

**`'none'` is a conscious homonym at three scopes** — same intent (“derive nothing here”), different axis. Do not rename one scope to “fix” the collision:

| Scope | Reading |
|---|---|
| `rollUpKinds: 'none'` | no Kind derives (D-S4-6) |
| Field `rollUp: 'none'` | this Field opts out after type merge |
| Aggregator `'none'` | always returns `undefined` |

### D-S4-4 — Core Fields are ordinary declarations

`data/fields/core-fields.ts` declares `name`, `start` (`min`), `end` (`max`), `kind` (text column), `parentId`, `segments`, `meta` and the computed `duration`. `name`, `start`, `end`, `duration` and `kind` declare `column`. `parentId`, `segments` and `meta` do not — they are Fields for the changeset, not Grid column candidates. **`progress` is not declared** (ADR 0008). The registry seeds itself with these and then adds the consumer's. There is no "core" branch anywhere downstream — that is what makes a `cost` column and a `start` column one code path.

A declaration whose `key` names a core Field throws `DuplicateFieldKeyError`. Core Fields always set `source` explicitly (`{ from: 'entry', field: 'start' }`, `{ from: 'compute', read }`). They must not take the omitted-source default, or `start` would be read from `meta.start`. Core `start`/`end` are not overridable; a consumer who wants a different rollup on their own Field uses a Field type, not an overlay on a core key.

The per-field comparator table (`data/change-set.ts`'s `coreComparators`) becomes each core Field's own `equals`. The exhaustiveness check narrows to the core set, as ADR 0005 §28 requires; a consumer Field supplies `equals` or gets `Object.is`.

### D-S4-5 — A bad declaration throws at construction

| Condition | Error |
|---|---|
| Two declarations share a `key` | `DuplicateFieldKeyError` |
| A declaration's `key` names a core Field | `DuplicateFieldKeyError` |
| Two declarations resolve to the same `{ from: 'meta', key }` | `DuplicateFieldSourceError` |
| `rollUp` names an unregistered Aggregator | `UnknownAggregatorError` |
| `type` names an unregistered Field type | `UnknownFieldTypeError` |
| An edit names an unregistered key | `UnknownFieldError` (already shipped; the registry widens its legal set) |

Construction is where a consumer can still fix it cheaply, and it keeps the commit path free of validation it would otherwise repeat on every transaction.

### D-S4-35 — Omitted `source` is `meta` under the Field key

The common call is `{ key: 'cost', type: 'money' }`. After resolution that is `{ from: 'meta', key: 'cost' }`. `{ from: 'meta' }` with no `key` is the same default. Write `{ from: 'meta', key: 'budget' }` only when the Document key differs. `{ from: 'entry' }` and `{ from: 'compute', read }` stay explicit.

This does **not** put `cost` on `Entry`. `Entry` stays closed (ADR 0005). Unknown top-level keys on ingest are still dropped. A declared Field is addressable as `update('t1', { cost: 500 })` and stored as `entry.meta.cost`. `entry.meta.team` for an undeclared passenger is unchanged. Filters that already read `entry.meta.team` keep working.

**What this must not break** (each row is a test in S4.1):

| Case | Result |
|---|---|
| `{ key: 'cost', type: 'money' }` and `meta: { cost: 500 }` on the input | `readField` returns `500`. Construction rollup sees it. |
| Construction rollup of a `'group'` whose children have `cost` | The parent gains `meta.cost` (the sum) even if it had no `meta`. Same precedent as the span pass writing `start`/`end`. |
| `{ key: 'cost' }` and no `meta` on the input | Read is `undefined`. `update({ cost: 500 })` creates `meta: { cost: 500 }`. `toJSON` writes that `meta`. |
| Input `{ id, name, start, end, cost: 500 }` (top-level, not in `meta`) | `cost` is dropped as an unknown top-level key, same as today. The Field reads `undefined` until someone writes `{ cost }` through `update` or puts it in `meta`. |
| `{ key: 'start' }` | `DuplicateFieldKeyError` at construction. The default cannot steal a core Field into `meta`. |
| `{ key: 'cost' }` and `{ key: 'budget', source: { from: 'meta', key: 'cost' } }` | `DuplicateFieldSourceError`. Two Fields must not share one `meta` slot. |
| `{ key: 'cost', source: { from: 'meta', key: 'budget' } }` over `meta: { budget: 1, cost: 2 }` | Reads `1`. The Field key and the Document key are different on purpose. |
| `toJSON` of an omitted-source Field | Writes the **resolved** source `{ from: 'meta', key: 'cost' }`. `fromJSON` does not depend on the construction default. |
| Whole-`meta` write after a declared Field exists | D-S4-2: `meta` row plus declared rows. Apply `meta` first. |
| Undeclared `meta.sourceSystemId` next to declared `cost` | Passenger still round-trips by reference. Declaring `cost` does not walk the rest of `meta`. |

Rejected: omitted `source` means a new top-level key on `Entry`. That reopens ADR 0005's rejected option (drop `meta`). A later core Field of the same name would collide with stored documents.

Rejected: force Field key and `meta` key to be identical, with no long form. A renamed Field over an old Document has nowhere to point.

Rejected: a dotted path in `key` (`'finance.cost'`). One `meta` key is a single segment. Nesting, if a caller ever needs it, is a computed Field or a flatter Document — not this default.

Core Fields are not this default (D-S4-4). A Field type does not carry `source` (`Omit<…, 'source'>`): `money` does not decide where a value lives.
