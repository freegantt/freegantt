# S4.1 — Field registry

**Slice:** S4 · **Step:** 1 of 11 · **Spec:** [`README.md`](./README.md) · **Decisions:** D-S4-1 – D-S4-5
**Prerequisite:** none · **Ends with:** `dataset.entries.update('t1', { cost: 500 })` commits one changeset row whose `field` is `cost`, and a misspelt key throws.

## 1. Decisions

### D-S4-1 — The types live in `model/`; one registry lives in `data/`, and it holds the whole declaration

`model/field.ts` is types only, like every other `model/` file. `data/fields/field-registry.ts` holds the one `FieldRegistry` a `DatasetState` owns.

```ts
// model/field.ts — types only
export type FieldKey = CoreFieldKey | (string & {});     // moves here from model/change-set.ts
export type AggregatorName = 'min' | 'max' | 'sum' | 'count' | 'none' | (string & {});
export type FieldTypeName = string & {};

export type FieldSource =
  | { from: 'entry'; field: CoreFieldKey }
  | { from: 'meta'; key: string }
  | { from: 'compute'; read(entry: Entry, ctx: FieldContext): unknown };

export interface Field<TValue = unknown> {
  key: FieldKey;
  type?: FieldTypeName;
  source: FieldSource;
  rollUp?: AggregatorName;
  equals?(a: TValue | undefined, b: TValue | undefined): boolean;
  formatValue?(value: TValue | undefined, ctx: FieldContext): string;
  column?: Omit<GridColumn, 'field'>;
}

/** A `Field` with `key` and `source` omitted — one bundle applied by name to many Fields. */
export type FieldType<TValue = unknown> = Omit<Field<TValue>, 'key' | 'source' | 'type'>;

/** Everything a value needs to be read or rendered as text, and nothing about a view. */
export interface FieldContext {
  readonly timeZone: string;
  readonly locale?: Intl.LocalesArgument;
  read<T>(entry: Entry, key: FieldKey): T | undefined;
  durationOf(entry: Entry): Duration;
}
```

The registry stores the **whole** declaration, `column` included. `data/` carries that sub-object and never interprets it; `view/` reads it back through the Dataset when it resolves Grid columns (S4.3).

Rejected: two registries, one in `data/` for the data half and one in `view/` for the presentation half, written by `api/`. One declaration stored twice drifts, and `fromJSON` would rebuild only one of them. ADR 0005 §31's "split at `api/`" is about *who sends what where*, and a read-time split satisfies it with one copy.

Rejected: `Dataset<TFields>` generic. ADR 0005 already rejected it — the parameter propagates through `Gantt`, `view/` and `layout/` to serve a boundary concern.

### D-S4-2 — One adapter reads and writes a `FieldSource`

`data/fields/field-access.ts` holds the only `switch` over `FieldSource` in `src/`:

```ts
export function readField(entry: Entry, field: ResolvedField, ctx: FieldContext): unknown;
/** Folds one field write into an entry-shaped `StoredEdit`, merging `meta` rather than replacing it. */
export function writeField(edit: StoredEdit, entry: Entry, field: ResolvedField, value: unknown): StoredEdit;
```

Adding a fourth source variant later changes this file and nothing else (open/closed). Every other layer asks for a value by **Field key** and never learns where it sits — which is what ADR 0005 §24 means by "`meta` is demoted from surface to storage".

**Edits stay entry-shaped inside the store.** `EntryEdit` widens to accept declared keys; `entries.update` folds each declared key through `writeField` before it stages, so `StoredEdit` keeps the shape S3's `layout/gesture-draft.ts` already builds. Nothing in the gesture path changes.

**`diffEdit` becomes Field-aware.** It consults the registry, so:

- `update('t1', { cost: 500 })` emits one row, `field: 'cost'`, `from: 400`, `to: 500`. No `meta` row.
- `update('t1', { meta: {…} })` emits one `meta` row carrying the whole object as authored, **plus** one row per changed declared key. Apply order within one entry is the `meta` row first, then the declared rows. Undo inverts every row and keeps the same order, so it restores exactly.

Rejected: a Field-keyed write set (`ReadonlyMap<EntryId, ReadonlyMap<FieldKey, unknown>>`). It reshapes S2's transaction machinery and S3's gesture drafts for a translation that one function already does.

### D-S4-3 — An Aggregator is always a registered name

Shipped: `min`, `max`, `sum`, `count`, `none`, `weightedMeanByDuration`. `data/fields/aggregators.ts` holds them; `DatasetOptions.aggregators` adds consumer ones by name. An unknown name throws `UnknownAggregatorError` at construction, never at commit time.

`rollUp` never takes a bare function — a name serializes into a Document and a function does not (ADR 0005).

### D-S4-4 — Core Fields are ordinary declarations

`data/fields/core-fields.ts` declares `name`, `start` (`min`), `end` (`max`), `progress` (`weightedMeanByDuration`), `kind`, `parentId`, `segments`, `meta` and the computed `duration`. The registry seeds itself with them and then adds the consumer's. There is no "core" branch anywhere downstream — that is what makes a `cost` column and a `start` column one code path.

The per-field comparator table (`data/change-set.ts`'s `coreComparators`) becomes each core Field's own `equals`. The exhaustiveness check narrows to the core set, as ADR 0005 §28 requires; a consumer Field supplies `equals` or gets `Object.is`.

### D-S4-5 — A bad declaration throws at construction

| Condition | Error |
|---|---|
| Two declarations share a `key` | `DuplicateFieldKeyError` |
| A declaration's `key` names a core Field | `DuplicateFieldKeyError` |
| `rollUp` names an unregistered Aggregator | `UnknownAggregatorError` |
| `type` names an unregistered Field type | `UnknownFieldTypeError` |
| An edit names an unregistered key | `UnknownFieldError` (already shipped; the registry widens its legal set) |

Construction is where a consumer can still fix it cheaply, and it keeps the commit path free of validation it would otherwise repeat on every transaction.

## 2. Files

| File | Job |
|---|---|
| `src/model/field.ts` | `Field`, `FieldSource`, `FieldType`, `FieldContext`, `RollUpContext`, `Aggregator`, `AggregatorName`, `GridColumn`; `FieldKey` moves here |
| `src/model/change-set.ts` | re-exports `FieldKey` from `field.ts`; keeps `CoreFieldKey` |
| `src/model/errors.ts` | `DuplicateFieldKeyError`, `UnknownAggregatorError`, `UnknownFieldTypeError`; `UnknownFieldError`'s comment corrected to S4 |
| `src/data/fields/field-registry.ts` | `FieldRegistry` — resolve against `fieldTypes`, store, look up, list rolling-up Fields |
| `src/data/fields/field-access.ts` | `readField`, `writeField` — the one `FieldSource` switch |
| `src/data/fields/aggregators.ts` | the shipped Aggregator table |
| `src/data/fields/core-fields.ts` | core Field declarations, with the comparators moved onto them |
| `src/data/change-set.ts` | `diffEdit` becomes Field-aware; `CORE_FIELD_KEYS` gives way to the registry |
| `src/data/entry-store.ts` | `update` validates against the registry and folds declared keys through `writeField` |
| `src/data/dataset-state.ts` | owns one `FieldRegistry` and the `FieldContext` |
| `src/api/dataset.ts` | `fields` / `fieldTypes` / `aggregators` options; `Dataset.fields` read view |
