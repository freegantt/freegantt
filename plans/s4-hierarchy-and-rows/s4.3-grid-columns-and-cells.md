# S4.3 — Grid columns and row cells

**Slice:** S4 · **Step:** 3 of 11 · **Spec:** [`README.md`](./README.md) · **Decisions:** D-S4-12, D-S4-13, D-S4-14 · **Closes:** issue #81
**Prerequisite:** S4.1 · **Ends with:** four columns in the grid pane, each formatted by its own Field, and `gantt.gridColumns = [...]` re-renders them with no remount.

## 1. Decisions

### D-S4-12 — `gridColumns` is names in display order, plus per-Gantt overrides

```ts
gantt.gridColumns = ['name', 'start', 'duration', { field: 'cost', header: 'Budget — site A' }];
```

A string names a Field and takes that Field's own `column` defaults. An object overrides this Gantt's presentation and never the data half. **The object form merges per-key** over the Field's `column` defaults: an omitted `header`, `width`, `flex` or `align` inherits the Field's value. Example: a Field declares `{ width: 90, align: 'end', header: 'Cost' }`; `{ field: 'cost', header: 'Budget' }` resolves to `{ header: 'Budget', width: 90, align: 'end' }`.

A name that is not a declared Field key is an `UnknownFieldError` — the same error an edit gets, from the same registry.

Default `gridColumns` is `['name']`, which is exactly what S1's single label column already draws. A Gantt that sets nothing looks unchanged. A name that is a Field but has no `column` is a `FieldNotColumnableError`.

`parentId`, `segments` and `meta` have no `column`. `kind` does — a Kind column is a real ask. `name`, `start`, `end` and `duration` do. Declaring `column` does not put the Field on the grid; `gridColumns` still lists what this Gantt shows.

```ts
// model/field.ts
export interface GridColumn {
  field: FieldKey;
  header?: string;
  width?: number;
  flex?: number;
  align?: 'start' | 'end';
}
/** What a consumer writes: a Field key, or a column object. */
export type GridColumnInput = FieldKey | GridColumn;
```

`cellRenderer` and `editable` are **not** on this type in S4 (I11: nothing unimplemented in the public surface). They arrive in S5 with the code that honours them.

Rejected: a `columns` config that also declares data (`{ id: 'team', value: t => t.meta.team }`). That is the two-shape design ADR 0005 replaced. A column names a Field; it never defines one.

### D-S4-13 — `LayoutInput.columns` is the one place the Field context meets the Row context

`view/grid-columns.ts` resolves `gantt.gridColumns` against the Dataset's Fields once per change, binding **this Gantt's** `locale` (G3 — settled). A headless `Dataset` with no `Gantt` does not format cells. `locale` does not travel in the Document.

```ts
// layout/ — plain data, no registry, no Dataset
export interface ResolvedColumn {
  key: FieldKey;
  header: string;
  width?: number;
  flex?: number;
  align: 'start' | 'end';
  /** Bound with this Gantt's locale and the Field's `formatValue`. */
  format(entry: Entry): string;
  /** Default sort order for this Field's stored value. Bound with this Gantt's locale. */
  compareStored(a: unknown, b: unknown): number;
}
```

`resolveColumns(gridColumns, fields, { timeZone, locale })` builds both closures. `layout/rows/sort.ts` reads `compareStored` from the column that matches `sort.field`; `RowSort.compare` overrides it when set (D-S4-28).

`layout/` never imports `data/` and never learns what a `FieldSource` is. `computeFrame` fills `FrameRow.cells` by calling `format` per column, in column order — the same "library-derived text, not consumer render output" rule `a11yLabel` already follows (`plans/01` §4).

`view/` also hands the same list to the DOM backend, so the header row and the body cells size from one description.

### D-S4-14 — `formatValue` returns text; a renderer never enters `data/`

`Field.formatValue` is DOM-free, returns a string, and fills the frame's cells. `GridColumn.cellRenderer` returns element descriptions and is applied by `render/` — S5. The split is the one `FrameBar.label` and `barRenderer` already use. Money stays a number in the store; `formatValue` (usually on the Field type) turns it into currency text at resolve time with the Gantt's `locale` (D-S4-13). Sort reads the stored value through `compareStored` on the same `ResolvedColumn` (S4.9). A renderer never enters `data/`.

This is also the boundary that keeps `data/` clean: a `Field.column` sub-object is plain data that `data/` carries; a renderer is code that `data/` must never hold. When S5 adds `cellRenderer`, it goes on the `Gantt`'s column, not on the Dataset's Field.

## 2. Files

| File | Job |
|---|---|
| `src/view/grid-columns.ts` | `resolveColumns(gridColumns, fields, { timeZone, locale }) → readonly ResolvedColumn[]` |
| `src/layout/column.ts` | `ResolvedColumn` — plain-data type, `layout/`-owned |
| `src/layout/frame.ts` | `LayoutInput.columns`; `cells` filled per column instead of `[entry.name]` |

| `src/render/dom/index.ts` | per-column width, flex and alignment; `.fg-row-cell` keyed by column key |
| `src/view/styles.ts` | column layout tokens; `.fg-row-label` stays the first cell's class (#81) |
| `src/api/gantt.ts` | `gridColumns` option and live property |

## 3. Tests

- `src/view/grid-columns.test.ts` — a string takes the Field's defaults; an object merges per-key over the Field's `column` defaults (omitted `width`/`align` inherit); an unknown key throws `UnknownFieldError`; `gridColumns: ['meta']` throws `FieldNotColumnableError`
- `src/layout/frame.test.ts` — `cells` has one entry per configured column, in order, and each came from that Field's `formatValue`
- `src/render/dom/index.test.ts` (dom) — four columns paint four cells; widths and alignment apply; a column removed prunes its nodes
- `src/api/gantt.test.ts` — `[S4-A1]`'s column half: a declared `cost` shows beside `start`; assigning `gridColumns` re-renders with no remount (bar nodes keep identity, I8)
