This step proves I5 on the hover path before any gesture writes data.

## 1. Decisions

### D-S3-9 — Capabilities resolve once, in `view/`, over a per-kind default table

`view/capability.ts` — `resolveCapabilities(interactions)`, `Interactions`, `CapabilityRule`.

Per-kind defaults when `interactions` says nothing:

| Kind | move | resize | select |
|---|---|---|---|
| `'span'` | ✅ | ✅ | ✅ |
| `'milestone'` | ✅ | ❌ | ✅ |
| `'group'` (or any `derivedSpanKinds` kind) | ❌ | ❌ | ✅ |
| consumer-defined | ✅ | ✅ | ✅ |

`linkCreate` and `edit` are **not** on `Interactions` in S3 (I11). `select` has no visual affordance — I14's hide half is vacant; the refuse half gates pointer and keyboard paths. `gantt.selection = …` does **not** consult `can('select')`.

### D-S3-6 — One `InteractionState` per Gantt, mutated in place

```ts
export interface InteractionState {
  hoveredItemId?: ItemId;
  selectedItemIds?: readonly ItemId[];
  resizableItemId?: ItemId;   // shell resolves once per hover/selection/interactions change
  movableItemId?: ItemId;
  // preview, cursorX, cursorLabel, pending — later steps
}
```

`applyState` reads resolved ids; it never calls `resolveCapabilities` (I14).

### D-S3-7 — `data-state` token projection

Fixed vocabulary: `hovered selected dragging ghost pending`. Tokens are **not** derived from `Object.keys` on a boolean record — `render/dom` projects `InteractionState` once. This step: `hovered` and `selected` only.

### D-S3-8 — Resize handles are one shared pair of nodes

`mount()` creates two `.fg-bar-handle[data-edge="start"|"end"]` nodes once; `applyState` positions them on `resizableItemId` or parks them (`hidden`). Cursor: `data-movable` on the bar (`no-inline-style-outside-geometry` forbids inline `cursor`).

### D-S3-5 (partial) — `SplitterHooks` → `SplitterContext`

Mechanical rename in S3.3's pointer base step is listed here in the original spec; may land in S3.2 or S3.3.

### D-S3-20 — Hover perf (`[S3-A3]`)

1,000-entry fixture, ≥200 mounted bars (widened `overscan`); assert no `computeFrame`, no node create/remove, O(changed items) `data-state` writes.
