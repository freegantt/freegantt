# S3.5 — Keyboard parity and the async veto

**Slice:** S3 · **Step:** 5 of 8 · **Spec:** [`README.md`](./README.md) · **Decisions:** D-S3-9 (keyboard), D-S3-13, D-S3-17
**Prerequisite:** S3.3 commit path · **Status:** done (unit/integration coverage; harness demo lands with S3.8's gate) · **Ends with:** a bar nudges by keyboard; the veto demo's async path holds a pending ghost.

## 1. Decisions

### D-S3-13 — Keyboard map; selection is the mode switch

| Keys | Nothing selected | Something selected |
|---|---|---|
| `↑`/`↓` | pan vertically | move selection to prev/next **selectable** row |
| `←`/`→` | pan horizontally | nudge by one snap unit |
| `Shift`+`←`/`→` | — | resize `end` by one snap unit |
| `Alt`+`←`/`→` | — | nudge without snapping |
| `PageUp`/`PageDown`/`Home`/`End` | pan | pan (never re-bound) |
| `Escape` | — | clear selection |
| `Enter` | — | no-op in S3 (editor is S5) |

Shipped default only — no `keyMap` option (I11); remap deferred to S5. One transaction per keypress (I6). `attachKeyboardEditing` refuses off the same `can()` as pointer.

### D-S3-17 — Async veto and `pending`

On pointerup, if `beforeEntryMove`/`beforeEntryResize` returns a promise: `InteractionState.pending = true`, preview stays at dropped position, no new gesture arms, keyboard editing refused. `.fg-bar[data-state~="pending"]` — reduced opacity default. Rejection = veto; rejection re-thrown async.

**Lock vs paint:** `pending` in `InteractionState` is paint; gesture machinery owns the arm lock beside the draft.

## 2. Files

| File | Job |
|---|---|
| `src/interaction/keyboard-editing.ts` | `attachKeyboardEditing` — one `keydown` listener on the container; mode switch on `ctx.selection.get()[0]` (D-S3-13): nothing selected is S3.7's to bind, something selected edits |
| `src/view/entry-gesture-context.ts` | `EntryGestureSession.nudge(direction, options)` — the keyboard's only write path |
| `src/view/gesture-pipeline.ts` | `GesturePipeline#stepPx` sizes one snap unit in px (reuses `#draftFor`/`#commit`, no parallel calendar path); `#awaitVeto`/`#pendingItemIds` implement D-S3-17 |
| `src/view/gantt-shell.ts` | Builds one shared `EntryGestureContext`, passed to both `attachEntryGestures` and the new `attachKeyboardEditing` (constructor-injected, same DI shape) |
| `src/data/event-bus.ts` | `EventBus<TEvents, TAsyncKeys>` — a handler for a `TAsyncKeys` name may return `Promise<void \| false>`; `emit` folds sync vetoes immediately, waits on any returned Promises otherwise |
| `src/view/event-bus.ts` | `AsyncCancelableEvent = 'beforeEntryMove' \| 'beforeEntryResize'`, `GanttEventHandler<K>` |
| `src/render/backend.ts` / `src/render/dom/index.ts` | `InteractionState.pendingItemIds`, `pending` `data-state` token |

**Decision — keyboard reuses the pointer pipeline, not a parallel one.** A keyboard step never computes
a calendar delta itself: `nudge()` asks `GesturePipeline#stepPx` for one resolved snap unit's pixel
width (`TimeScale.widthForDuration`), then feeds that through the exact same `#draftFor`/`#commit` a
mouse drag's `commit(dxPx)` already runs. `interaction/keyboard-editing.ts` never resolves a pixel or
an `Instant` itself (I1) — it only picks a `direction`/`suspendSnap` and hands them to `session()`.
Alt (`suspendSnap: true`) still sizes the step off the same tick, it just skips grid alignment on
write, same distinction the pointer path's Alt already makes (D-S3-12).

**Decision — one `EntryGestureContext`, two attachments.** `GanttShell` builds the context object once
and passes it to both `attachEntryGestures` (pointer) and `attachKeyboardEditing` (keyboard) — both
drive the same `GesturePipeline.session()`, so there is no value in a second, narrower context type.
`attachKeyboardEditing` adds its own `keydown` listener on the container alongside
`attachEntryGestures`'s existing one (Escape-clears-selection) rather than merging into it — the two
listeners check disjoint `e.key` values and stay in their own modules.

## 3. Tests

- `src/interaction/keyboard-editing.test.ts` — D-S3-13 both modes (nothing/something selected), all
  four arrow directions, Shift (resize end edge), Alt (`suspendSnap`), row navigation skipping an
  incapable row, a refused `session()` (incapable or pending) no-op, `preventDefault` only for a
  handled key, `detach()`.
- `src/view/gesture-pipeline.test.ts` — `nudge()` (move forward/back, resize edge, `suspendSnap`
  skips grid alignment) and async veto/pending (`setPending` called with the gesture's item ids then
  cleared, `session()` refuses to arm while pending, a Promise resolving `false` commits nothing, a
  sync result never touches `setPending`).
- `src/api/gantt.test.ts` — real `keydown` integration: `ArrowRight` nudges the selected entry through
  one transaction with undo, empty selection is a no-op, `Shift+ArrowRight` resizes, `ArrowDown` moves
  the selection with no dataset write; a real drag's `beforeEntryMove` handler returning a `Promise`
  paints `.fg-bar[data-state~="pending"]` until it settles, both for `true` (commits) and `false`
  (does not).
