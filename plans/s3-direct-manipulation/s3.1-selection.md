# S3.1 — Selection

**Slice:** S3 · **Step:** 1 of 8 · **Spec:** [`README.md`](./README.md) · **Decisions:** D-S3-6 (partial), D-S3-7 (partial), D-S3-10, D-S3-22 (selection events)
**Prerequisite:** none · **Status:** done (2026-08-30) · **Ends with:** clicking bars in `harness/index.html` highlights them; a readout shows the selection.

Selection lands before capabilities or drag so the shell owns `InteractionState` and `applyState` diffing before the hot path adds more tokens.

## 1. Decisions

### D-S3-10 — Selection is a set of **Entry** ids on the **Gantt**; Items are what gets painted

An Entry with Segments produces several Items (`01` §2.4), and "this segment is selected but its siblings are not" means nothing at this slice. So the authored concept is entries:

```ts
get selectedIds(): readonly EntryId[];                  // stored type out: complete, branded
set selectedIds(ids: readonly (EntryId | string)[]);    // loose in; live, and runs the same
                                                        // cancelable sequence a click runs
```

**Loose in, complete out** — the same asymmetry `entries.get/update/remove` already ship. The getter stays branded; the setter accepts loose ids.

**Names (#113, renamed after S3.1 shipped).** The pair is `selectedIds` and `selectedEntries`: same stem, and the suffix is the only difference, so the reader tells ids from `Entry` records without opening the types. The concept keeps its glossary word in the events (`beforeSelectionChange`/`selectionChange`) and in the shell's own `#selection`. The shipped names `selection`/`selectionEntries` are retired — one of them carried no axis word at all.

On the `Gantt`, not the `Dataset` — pointer/gesture events fire on the Gantt and data events on the Dataset, and two Gantt instances bound to one Dataset must be able to have different selections. `InteractionState.selectedEntryIds` carries the same Entry ids (#185 retired the Item-keyed `selectedItemIds`): a backend resolves which bars those Entries drew.

Pointer semantics (S3.1 ships these; capability filtering arrives in S3.2): plain click replaces; ctrl/⌘-click toggles; shift-click extends over the current row order; click on empty timeline clears; Escape clears. Selection is written on **pointerup**, never pointerdown (`01` §9), and not at all if the gesture armed into a drag (S3.3+).

### D-S3-22 — Selection events

Added to `GanttEventMap`: `beforeSelectionChange`/`selectionChange`.

```ts
export interface SelectionChange { readonly from: readonly EntryId[]; readonly to: readonly EntryId[]; }
```

Selection opens **no** transaction — it is Gantt state, not a `Dataset` write (`[S3-A1]` scopes data gestures separately).

### D-S3-6 / D-S3-7 (this step only)

`GanttShell` owns one long-lived `InteractionState`; this step wrote `selectedItemIds` from `#selection` via `itemId()`. **That sentence was the bug (#185).** `itemId()` names Segment 0, so an Entry with Segments painted one bar of the several it drew. Issue #185 superseded this step: the field is `selectedEntryIds`, the shell writes `#selection` straight through, and the backend paints every bar of a selected Entry from the frame it synced. `applyState` still paints the `selected` token via `data-state` (D-S3-7's five-row projection — only `hovered` and `selected` exist until S3.3 adds `dragging`/`ghost`/`pending`).
