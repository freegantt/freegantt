# S2.1 — Stores and the reactivity façade

**Slice:** S2 · **Step:** 1 of 7 · **Spec:** [`README.md`](./README.md) §2 D-S2-1, D-S2-2, D-S2-3, D-S2-4, D-S2-5, D-S2-21
**Baseline:** `main` @ `ed3b935` · **Ends with:** `data/` holds the entries and nothing renders differently.
**Blocked on:** [`OPEN-QUESTIONS.md`](./OPEN-QUESTIONS.md) **OQ4** (does `layout/` bind to a `Dataset` or a snapshot — decides §3) and **OQ5** (the class's name — decides §2.4). Both closed: OQ4 as option (a) — `Viewport.bind` takes a snapshot; OQ5 as `DatasetState`, not `DatasetData` (see OPEN-QUESTIONS.md).

This step moves the entries out of `api/dataset.ts`'s constructor and into a real store, and it lands
the two layer changes that make the rest of S2 possible. It adds **no** mutation: at the end of it a
`Dataset` still cannot be edited, and every existing test passes with no assertion changed — only the
`dataset.entries` read sites move to `dataset.entries.all`.

That symmetry is the review, the same way S1.11a's was: `pnpm verify` and `pnpm test:e2e` green at the
parent commit and green at the head, with no behaviour between them.

## 2. API

### 2.1 `model/dataset.ts` — the contract changes (D-S2-2)

```ts
export interface EntryStoreView {
  /** The **committed** array. Identity changes only when a transaction commits (D-S2-3), and
   *  it does not show a transaction's own uncommitted writes — `get`/`has`/`size` do (D-S2-21). */
  readonly all: readonly Entry[];
  get(id: EntryId): Entry | undefined;
  has(id: EntryId): boolean;
  readonly size: number;
}

export interface Dataset {
  readonly entries: EntryStoreView;
  readonly timeZone: string;
}
```

### 2.2 `data/reactivity.ts` — the façade

```ts
/** The only file that sees the reactive dependency (plans/04 §1, docs/02 §3.8).
 *  Instance-scoped: nothing here holds module-level state (I2). */
export interface Signal<T> { get(): T; set(value: T): void }
export function signal<T>(initial: T): Signal<T>;
export function computed<T>(compute: () => T): () => T;
export function batch(run: () => void): void;
```

Exactly the three primitives S2's own code calls. `effect` is not exported: nothing in S2 subscribes
to a derived value — delta delivery is the event bus's job (D-S2-4) — and an unused export is the
I11 defect B8 lands to catch.

The file's leading comment must contain `the only file that sees the reactive dependency`
(`require-invariant-header`, `docs/02` §3.8).

### 2.3 `data/entry-store.ts`

```ts
export class EntryStore implements EntryStoreView {
  get all(): readonly Entry[];                // committed only; rebuilt on commit (D-S2-3)
  get(id: EntryId): Entry | undefined;       // reads through the write set once S2.2 lands (D-S2-21)
  has(id: EntryId): boolean;                 //   "
  get size(): number;                        //   "
  /** Children of an entry, in insertion order. Built as a `computed` over the revision signal. */
  childrenOf(id: EntryId): readonly Entry[]; //   "

  // Mutators land in S2.3. They take a TxToken only data/transaction.ts can mint, so they are
  // unreachable until S2.2 exists — this is the "types do half the work" half of docs/02 §3.6.
}
```

There is no write set to consult in this step — S2.2 introduces it — so the four reads above go
straight to the committed indexes here, and gain the overlay in S2.2 with the transaction that fills
it. Write them so that adding the overlay is one branch at the top of each, not a restructure.

`byId` is the primary index and is what `get`/`has` read. `byParent` backs `childrenOf` and is what
`remove`'s descendant walk (D-S2-10) will use in S2.3. Both are `computed` over one revision
`signal`, so a transaction that touches fifty entries rebuilds each index once, at the first read
after the commit — not fifty times during the body.

### 2.4 `data/dataset-state.ts` (OQ5: `DatasetState`, not `DatasetData`)

```ts
export interface DatasetStateOptions {
  entries: readonly EntryInput[];
  timeZone: string;
  dateOnlyEnd?: DateOnlyEndRule;
}

export class DatasetState implements Dataset {
  readonly entries: EntryStore;
  readonly timeZone: string;
  readonly dateOnlyEnd: DateOnlyEndRule;
  /** The one `Date.now()` read this Dataset performs, via time/'s `now()` (CONTEXT.md,
   *  Reference date). Fixed for the Dataset's lifetime; S2.3's derived-span initialization reads it. */
  readonly referenceDate: Instant;
}
```

*— partly retired by ADR 0012 (Build 1, 2026-09-11): "S2.3's derived-span initialization reads it" no
longer holds, since that fill is deleted (see `s2.3-mutation-api.md`'s own note). `DatasetState.
referenceDate` itself stands; other callers (date lines' "now") still read it.*

`api/dataset.ts`'s `Dataset` becomes a façade that owns one `DatasetState` and delegates `entries`,
`timeZone` and `dateOnlyEnd`. Its constructor signature does not change.

## 3. Read-site migration

Three call sites read `dataset.entries` as an array today. Each becomes `dataset.entries.all`:

| File | Line context |
|---|---|
| `src/layout/viewport/viewport.ts` | `bind()` builds `ScaleBinding.entries` |
| `src/view/gantt-shell.ts` | `render()`'s `LayoutInput.entries` |
| `src/view/gantt-shell.ts` | `reveal()`'s `findIndex` scan |

`LayoutInput.entries` stays `readonly Entry[]` and `ScaleBinding.entries` stays `readonly Entry[]`:
`layout/` takes a snapshot and has no interest in a store.
