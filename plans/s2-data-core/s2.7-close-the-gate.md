## 2. `[S2-A4]` — the e2e box

`e2e/data.spec.ts`, against `harness/data.html`:

- Click **Rename**. Assert the log gains a row naming the store, the entry id, the field `name`, and
  **both** `from` and `to`, with `from` the value on screen before the click.
- Click **Move +1 day**. Assert two rows — `start` and `end` — each with `from` and `to`.
- Click **Undo**. Assert a row tagged `origin: undo` whose `to` is the original value.

`from` is what makes this falsifiable: a log built by re-reading the dataset can produce `to` and can
never produce `from`, so the assertion tests the changeset contract rather than the panel.

The four `*-is-removable` rules land with the steps that create their leaves (D-S2-23); what belongs
to **this** step is their red tests — `scripts/guard-red-test.mjs` already proves
`.dependency-cruiser.cjs` blocks a layer violation, and each leaf gets the same treatment: a fixture
importing it from a second file must fail the build. A removability claim with no red test is exactly
the `AUTO`-over-nothing defect D-S1.11-11 exists to catch, one file over.

A rule that cannot land honestly gets its `docs/01` row corrected to `PLANNED (Sn)` naming the slice
that lands it. `PLANNED` is the sanctioned way to say "documented before written"; `AUTO` over a
missing rule file is the defect D-S1.11-11 exists to catch, and this step must not add a new instance
of it.

`no-kind-literal` is the one rule here that is **not** already promised by `docs/01`. CLAUDE.md's entry-kinds rule — *"no `if (kind === ...)` chains outside them"* — has had no guard since it was written, and D-S2-22 is the first slice with a kind-dependent behaviour in `data/` that could break it. It is one `no-restricted-syntax` entry plus the usual four fixtures. It is also net-new scope in a slice already judged too large, so it is the reviewer's call: land it, or drop the guard and drop the foot-gun row with it. A row promising an answer that does not exist is the defect this step exists to remove.

Two rows need correction regardless:

- **B3 `no-random`** allowlists `src/data/id.ts` "(id minting only)". S2 mints `ChangeSetId` from a
  per-instance counter — a module-level random generator is I2's failure — so no such file exists.
  The allowlist entry names a path that was never written; correct it to say so.
- **The dependency-count row** is re-checked, not re-edited: S2 adds no runtime dependency, and
  `plans/04` §1.1's rejected list is where a third candidate goes if one is ever proposed.
