Replay a ChangeSet without the extender

Strong in-process

src/data/history.ts · src/data/transaction.ts · src/api/dataset.ts

Before — two commit seams

flowchart TB
  U[consumer undo] --> D[Dataset]
  D --> S[DatasetState]
  S --> H[History]
  H -.leak.-> C[commitChangeSet]
  C --> ST[EntryStore]
  H --> B[change bus]
  classDef leak stroke:#dc2626,stroke-width:2px;
  class H,C leak

After — one replay interface

flowchart TB
  U[consumer undo] --> D[Dataset]
  H[History adapter] --> D
  D --> R[replay ChangeSet]
  R --> ST[EntryStore]
  R --> B[change bus]
  classDef deep fill:#0f172a,stroke:#334155,color:#e2e8f0;
  class D,R deep

Problem. Undo cannot call transaction() or it re-runs the extension hook and the Rollup, so History leaks across the commit seam via commitChangeSet.

Solution. One named replay operation on the Dataset interface (or a WeakMap friend function) that writes exact ChangeSet rows and skips the extender.

  • locality: invert and replay sit in one module
  • leverage: a consumer History adapter becomes possible
  • interface stays small; implementation absorbs the second path
Aligns with ADR 0007 if replay is not a public class method. Does not reopen ADR 0006.

Consumer Dataset interface

Already deep. A human and an agent learn six names:

dataset.entries.update(id, { start })
dataset.transaction(() => { … })
dataset.on('change', ({ changeSet }) => { … })
dataset.undo()          // void; result arrives on change
dataset.canUndo
const doc = dataset.toJSON()
Dataset.fromJSON(doc)

The harness uses those same verbs. That is leverage. Agents should start at src/api/dataset.ts and CONTEXT.md (History, Document, ChangeSet). Do not start at commitChangeSet.
