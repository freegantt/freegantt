C1 — One deep item-production seam

STRONG FIXED 2026-08-31

Files. layout/items/: item.ts (types), item-emitter.ts (registry), emit-items.ts (emitRow), span/group/milestone-emitter.ts.

Problem

Six files form one interface (a Kind → Items producer), spread with no semantic reason. The exported ItemEmissionContext is unused by every emitter (speculative generality), and emitRow defaults to a fresh registry per call, hiding the per-Gantt invariant. "emit" also collides with the event-bus emit (rule #7).

Solution. One deep seam produceItemsForRow (or ItemProducer) that owns type + registry + fallback; the per-kind producers stay private behind it; drop ctx; make the registry required.

Benefit (locality, leverage). A caller and an agent learn one name; the fallback rule, the three shipped producers, and the seam live in one place; one test surface. Deleting the split concentrates rather than spreads.

Folds up: N1 (emit overload), St1 (unused ctx), St4 (registry default), St5 (3 near-copy emitters), A1 (6-file split), N2 (file/function mismatch).

C2 — Restore the four computeFrame stages as real seams

WORTH EXPLORING NOT DONE — deferred to S4.8

Files. layout/frame.ts.

Problem

The spec (D-S4-19) and the comment present resolve → emit → pack → place as named stages, but in the code they are inline statements inside one interlocked loop; row and bar construction are not independently testable. S4.8 next packs lanes — it will grow this loop unless the stage is a seam.

Solution. Extract placeRow(planned, items, scale, …): { row, bars } so each stage is a function with one reason to change.

Benefit (locality, leverage). S4.8 packs height inside one function, not the loop; each stage’s test is one call; computeFrame becomes thin orchestration.

C4 — Record the S7 post-rollup hook now; do not wire it in S4

JUDGEMENT / FLAG NOT DONE — record as S7 prerequisite ADR

Files. data/transaction.ts:242 (extender hook), :277 (rollup).

Problem

Today the commit sequence is extender → rollup, fixed order, and every invariant holds (one hook call structural, single rollup importer, no-silent-rewrite at rollup.ts:182). But S7’s schedule() occupies the extender slot and can only write before the rollup. If scheduling must propagate dependency-caused shifts onto already-rolled-up parents, transaction.ts becomes the file S7 edits — an OCP breach this slice promised to avoid.

Solution. Record the need for a postRollup hook (or explicit commit sequence) as an S7 prerequisite ADR now, so S7 does not re-derive it by editing the transaction.

Benefit. The single-write contract keeps one owner; S7 slots behind the rollup without touching core.

Top recommendation

Do the three cheap real breaks first — A4 (export RowHeightMode), A5 (rows → rowSource), A10 (drop PlannedRow.kind) — then C1: collapse the six item files into one deep produce seam, dropping the unused ItemEmissionContext and making the registry required. This is the newest code, still settling, and the cheapest place to set the shape before S5 starts registering emitters from outside the library. It buys the most leverage (one seam a caller and an agent learn) for the least churn, and it removes a genuine concept collision now rather than after S5 hardens the surface.
