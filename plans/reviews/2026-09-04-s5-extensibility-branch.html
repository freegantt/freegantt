What is good

The slice earns its structure. Worth naming before the criticism, because the findings below are refinements of a design that already holds:

  • The dogfood gate is real. extensions-public-only is a dependency-cruiser rule with a red-test behind it, so tooltips(), contextMenu() and inlineEditing() genuinely cannot reach a back door. That is what makes [S5-A1] a proof and not a claim.
  • One registration mechanism, not five. layout/registration-table.ts (#154) is a stack per key with a per-registration disposer. Commands, renderers, item producers, kind defaults and plugin columns all sit on it, which is why "disposing one plugin never disturbs another's registration on the same key" is one property tested once, rather than five near-misses.
  • Precedence is stated once per axis. resolveCapabilities holds consumer → plugin → library in three lines. RendererRegistry#resolve holds consumer → plugin in two. Neither is re-derived at a call site.
  • Escape folded into the keymap. Newest-first resolution gives "the innermost popup wins" for free, and deletes the bespoke document-capture stack it replaced.
  • The comments carry design rationale, not restatement. Nearly every non-obvious line says which decision it implements and what broke without it.

Correctness

Two confirmed defects and one design gap. Both defects are in extensions/features/inline-editing.ts, the largest new plugin (458 lines, one setup() closure).

C1 · confirmed

The cell editor never repositions on resize

src/extensions/features/inline-editing.ts:287 · findCell at :78

function findCell(container, entryId, field) {
  const row = container.querySelector(`.fg-row[data-entry-id="${...}"]`);   // descendants only
  ...
}
// the one call site passes the .fg-row element itself as `container`:
const detachResize = ctx.view.overlay.onResize(() => {
  const cell = findCell(row, entryId, field);      // always undefined
  if (cell) position(wrapper, cell);               // never runs
});

Why. Element.querySelector matches descendants, never the element itself, and .fg-row never nests (render/dom/index.ts:643). So findCell(row, …) returns undefined for every call and the resize reposition is dead code. Verified with a happy-dom test.

Effect. Resize the window, or change a column width, while a cell editor is open: the editor stays at its old offset, floating away from its cell.

Fix. The row is already the scope — row.querySelector(`[data-field="…"]`) is the whole lookup. The entryId parameter is not needed here. Note the name and the doc also disagree with the use: findCell's doc says "scoped to this Gantt's own container", and its one caller passes a row.

C2 · confirmed

An invalid value plus a double-click orphans a live editor

src/extensions/features/inline-editing.ts:391, :342, :351, :368

// openFor assumes closeSession always closes:
if (session) closeSession('commit');        // :391
...
session = current;                          // :368  — overwrites, no teardown

// but commit() declines when the value will not parse:
const result = control.read();
if (!result.ok) {
  markInvalid(wrapper, control.focusTarget);
  this.settled = false;                     // :342  — session stays open
  return;                                   //        teardown() never runs
}

Repro. Open the editor on cell A. Type a value the Field's parseValue rejects. Double-click cell B. closeSession('commit') declines, session is then reassigned to B's, and A's wrapper stays presented in the overlay with its focusout listener, its Escape handler and its focus trap all live.

Effect. A ghost editor on screen, two Escape handlers racing, and a focus trap with no owner. The plugin's own disposer only closes session, so the orphan survives uninstall.

Fix. Make the refusal legible at the call site: closeSession should return whether it closed, and openFor should bail when it did not. The deeper cause is C2b below.

C2b · design

settled is a latch the caller sets and the callee clears

closeSession writes current.settled = true, then calls commit(), which may write this.settled = false to stay open. One flag, two owners, opposite directions. The name says "this session is finished" and the code uses it as "a close is in flight". Both C2 and any future "did it actually close?" question come from that inversion. A commit(): boolean that owns its own outcome removes the flag entirely.

C3 · API gap

Popup has no way to tell its owner it closed

src/extensions/popup.ts · src/extensions/features/context-menu.ts:113

The code says so itself: "Popup dismisses itself (Escape, an outside pointer, scroll) with no callback out (a real gap this step found no need to close…)". The consequence is visible one screen up: after a self-dismiss, contextMenu()'s onDocumentClick and onDocumentKeydown stay attached to document until the next openAt() or plugin disposal, guarded only by an isOpen poll on every click and keystroke in the page.

Why it matters beyond this file. createPopup is public (api/index.ts). Every third-party plugin that builds a popup with side state inherits the same choice: leak the listeners, or poll isOpen. One onDismiss?: (trigger: DismissTrigger) => void on PopupOptions closes it for everyone, and lets contextMenu() drop the isOpen guards.

Naming

N1 · check 4 fail

Overlay now names two concepts

Read the call sites aloud, which is the repo's own test:

overlay.present(node)"present this in the overlay" — true
overlay.render(desc)true
overlay.contains(target)asks the container, not the overlay layer
overlay.elementForEntry(id)returns a timeline bar, which is not in the overlay
overlay.paneBounds.timelinethe pane's rect
overlay.boundsthe container's rect

Two of six members are overlay work. Four are "this Gantt's own DOM geometry and identity" — the thing a document-level listener asks about. This is the #7 precedent exactly: one word covering two concepts, and nothing at the call site saying which.

Split, do not rename. Keep Overlay as { present, render } — the mount layer, and honest. Move the other four onto a second member whose name is the question they answer, e.g. ctx.view.dom. Then ctx.view.dom.owns(target) and ctx.view.dom.barFor(entryId) read true, and the harness gains a legal way to reach barFor without a raw selector (see H2).

N2 · check 1

emit is one verb doing two jobs

emitBeforeEntryEdit(payload): boolean | Promise<boolean>   // asks, and the answer is a veto
emitEntryEdit(payload): void                              // tells, nothing comes back

"Emit" says a thing went out. It does not say a decision comes back, and a plugin author reading the first line has no reason to check the return value. The codebase already has a word for the returned refusal — Veto (CONTEXT.md), and Propose for the sequence (GanttShell#proposeChange). proposeEntryEdit / announceEntryEdit reads true and reuses vocabulary the glossary already owns.

N3–N5 · minor

Three smaller name drifts

  • ctx.view.resolveTooltip(entryId) returns an ElementDescription — the tooltip's body, not a tooltip. Its sibling is already resolveTooltipColumns. resolveTooltipContent makes the pair read straight.
  • findCell's doc says "scoped to this Gantt's own container"; its one caller passes a row (see C1). The name outlived its use.
  • date-input.ts's onCommit doc names "its own onceCommitted guard" in inlineEditing(). That guard is called settled. A comment naming a symbol that does not exist is the kind of drift the repo's own #7 rule exists to stop.

The harness, reviewed as CLAUDE.md requires

H2 · API gap

The harness re-derives elementForEntry with a raw selector

harness/main.ts · harness/plugins.ts, both in the popup demo

const anchor = document.querySelector(`#gantt .fg-bar[data-item-id="${itemId(selected)}"]`);

The library already computes exactly this — Overlay.elementForEntry(id), added in S5.5 for contextMenu()'s keyboard opener. The harness cannot reach it: popupDemo() stashes the Popup out of setup() but not the Overlay, so the button handler has no door. It reaches for .fg-bar and data-item-id instead — two internal DOM contracts, from consumer code.

This is the evidence, not the bug. Fixing the harness alone hides it. The gap is that "the DOM node for this entry" is only reachable from inside a plugin's setup(), when it is a perfectly ordinary thing for app code to want. It is the same gap N1's split would close.

H3 · API gap

A cell renderer can only see the formatted string

// harness/plugins.ts — un-formatting the library's own output to get a number back
function overBudget(formatted: string): boolean {
  const amount = Number(formatted.replace(/[^0-9.-]/g, ''));
  return Number.isFinite(amount) && amount > BUDGET_THRESHOLD;
}

CellRendererContext carries { entry?, row, column, value: string }. value is already through formatValue, so a renderer that wants to branch on magnitude has to parse '$1500' back with a regex. The in-repo comment defends this as "honest about the value it actually renders", and that argument holds for what is painted — but it is not an argument for withholding the number.

The context already reaches entry, yet reading entry.meta.cost is not the answer either: a compute-sourced Field has no stored home, and the whole point of ADR 0005 is that a consumer never reaches into meta. Add the resolved value the Field registry already produced: rawValue: unknown beside value: string. The library computes it either way.

logEverything(), selectionShortcuts() and popupDemo() appear character-for-character in both harness/main.ts and harness/plugins.ts — about 70 lines. harness/plugins/ already exists and already holds weekend-shading.ts and buffer-kind.ts; these three belong beside them. SP1 · wrong

Four different refusals all look like "nothing happened"

s5.8-inline-editing.md §1 (F11, F12) vs src/extensions/features/inline-editing.ts

The spec is unusually specific here:

"…the cell refuses to open the default editor at all, with the invalid state and a reason naming it (data-state~="invalid", "this field carries a time of day; the default date editor cannot show it")."
"…every other shipped type falls back to the invalid state on open, refusing to edit inline rather than silently parsing wrong."
// openDate — F11
if (ctx.dataset.time.startOfDay(raw) !== raw) return;      // bare return
// openFor — F12
if (!date && !canOpenGeneric(field)) return;               // bare return

No wrapper mounts, no data-state="invalid", and the reason text appears nowhere in the source. The tests encode the shipped behaviour rather than the spec's: both assert querySelector('.fg-cell-editor') is null — while the neighbouring parseValue-fails-on-commit test correctly asserts .fg-cell-editor[data-state="invalid"] is present. The mechanism exists; the two open-time paths do not use it.

Why this is more than a spec nit. A user double-clicks a cell and gets nothing, with four indistinguishable causes: the column is not editable, the entry's kind is rolled up, the instant carries a time of day, or the Field has no parseValue. Two of those are "this cell is not editable" and two are "this cell is editable but this editor cannot show it" — the difference is exactly what the spec asked to be visible. It is also the S5.11 a11y pass's problem to inherit: a silent no-op announces nothing.

ST1 · hard

Comment prose has drifted well past the ASD-STE100 rule

CLAUDE.md is explicit and unconditional: "Short sentences: keep sentences to 20 words for instructions and 25 words for descriptions" and "One instruction per sentence." Most new doc comments on this branch break both, often by a factor of three:

// api/plugin.ts — one sentence, ~50 words, three ideas
"S5.1 ships `dataset`, `gantt`, `events` and `disposables` only — every other member

A2 · GanttShell's constructor holds a module

src/view/gantt-shell.ts — 1,740 lines (+866 this branch), ~50 private fields, ~90 members, constructor 523–1028

After — the ports are their own module

Problem. The 200-line closure that builds a plugin's ports is a module living inside a constructor: it has one job, one set of collaborators, and no test that reaches it except through a whole mounted Gantt. Six of its fifteen ports are the same six lines with different nouns:

  • one answer to "is this mine?", not three
  • leverage: closes H2's harness gap too
  • a third-party plugin stops guessing
Worth exploring in-process

A4 · Every feature plugin re-invents scoped document listening

12 document.addEventListener calls across src/extensions/

Problem. A plugin must listen on document (its targets are nodes it never created), then decide whether the event is its Gantt's. Three plugins and popup.ts each write that guard by hand, each remembers its own removeEventListener with the matching capture flag, and one of them forgets the guard entirely. Two Gantts on one page is the failure mode, and B1 in the bug hunt already found it once.

Solution. ctx.view.onDomEvent(type, handler, opts) — listens on document, filters to this Gantt, and registers its own removal in ctx.disposables. Twelve pairs of add/remove plus four hand-written guards become twelve one-liners that cannot be got wrong. Pairs naturally with A3: the handler receives the resolved target, not a raw node.

Sequence it after A3 — on its own it is a convenience; with A3 it is the whole plugin-to-DOM story in one seam.
Worth exploring

A5 · inlineEditing()'s session wants to be an object

src/extensions/features/inline-editing.ts — 458 lines, one setup() closure, 15 nested functions

Problem. OpenSession is a data record with methods that reach back out to closure-scope functions (teardown(this)), and the settled flag is written from both sides (C2b). Both confirmed defects on this branch live in this file, and both are locality failures: the state that decides whether an editor is open is spread across a module-level let, a record field, and two functions that each half-own it.

Solution. A CellEditorSession class owning mount / commit(): boolean / revert() / reposition(), and setup() holding one session: CellEditorSession | undefined. commit() returning its own outcome removes settled, which removes C2. The class is testable without a mounted Gantt, which the closure is not.

Speculative

A6 · Cheap wins

  • Column lookup is O(rows × columns²) per frame. gantt-shell.ts's resolveCellRenderer does resolvedColumns.find(c => String(c.key) === columnKey), and render/dom/index.ts:699 calls it once per visible cell. A Map<string, ResolvedColumn> built in ColumnChrome.setResolvedColumns makes it O(1) and serves isColumnEditable / isResizable / isMovable / resolvedColumn at the same time. Not a hot-path invariant breach — this is the full render pass, not hover — but it is free.
  • Repeated switches in column-gestures.ts. if (grabbedKind === 'resize') … else if (grabbedKind === 'reorder') appears in move, commit and cancel. Two small strategy objects, one grabbed reference, and the cascade disappears — the same shape core-commands.ts's own registerColumnStepCommand already uses to collapse four near-identical commands into one.
  • A four-arm nested ternary seeds input.value in openGeneric. A named seedText(field, raw, cell) reads as a sentence.
  • createPopup's open() is ~70 lines of four inline if (dismissOn.includes(…)) blocks. A table keyed by DismissTrigger makes adding a fifth trigger a row, and pairs with C3's onDismiss.
