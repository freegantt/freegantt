Standards

St1 · plans/02 §6 still publishes a retired knob

Hard

plans/02 §6: “fromJSON without rollUp uses identity — parents keep stored values and do not maintain them.” D-S4-7 and D-S4-15 forbid a public rollUp function. The documented call is fromJSON(doc, { aggregators }). Dataset-level none is rollUpKinds: 'none'. One name per concept (plans/02 §1, CLAUDE.md #7). An implementer who codes the §6 sentence will ship a second knob the slice already rejected.

Fix. Replace that sentence: omit aggregators and a named Aggregator throws; Document rollUpKinds: [] keeps stored parents.

St2 · X2 — two things named 'group' on the row pipeline

Hard (blocking)

One meaning per word. D-S4-23’s table documents the collision; it does not remove it. PlannedRow is not public, so rename to 'header' (option A) costs no app-author call. Option B keeps the homonym in every kind === 'group' in computeFrame and in tests. README §12 already blocks S4.6 until a pick.

St3 · FieldContext.locale vs Gantt locale

Judgement

Q20 / D-S4-13: a headless Dataset does not format cells. Locale binds at column-resolve time. s4.1 still puts locale? on FieldContext, which lives on the Dataset. That invites Dataset-side formatValue the settled answer forbids. Drop locale from FieldContext, or mark it unused by format (format reads the bound closure only).

Sp2 · Default sort comparer rides visible columns

Wrong vs D-S4-13

Problem

D-S4-28: RowResolutionInput carries the same ResolvedColumn[] as LayoutInput.columns. Those columns are what this Gantt shows. sort: { field: 'cost' } with gridColumns: ['name'] then has no compareStored for cost. Sort falls to the shipped fallback and drops Field-type compare and Gantt locale. Sort is a Field question. Visible columns are a Grid question. Tying them couples view config into ordering.

Fix. Resolve compareStored for every declared Field (or for the sort key alone) at the same Gantt locale bind. Cells still use LayoutInput.columns. Sort does not require the Field on the grid.

Sp4 · ADR 0005 “split at api/” vs one registry

Worth exploring

ADR 0005: api/ sends the data half to data/ and the presentation half to view/. D-S4-1 stores the whole declaration, including column, in the Dataset registry and rejects two copies. That is cargo, not a call-graph leak, if data/ never calls formatValue and never paints. Keep the one-store rule; add one agent gotcha: data/ carries column bytes and does not interpret them. Do not reopen two registries.

Architecture — deepen or fold

In-process modules. One adapter is hypothetical; two adapters make a real seam.

A1 · Fold D-S4-19’s whole-list emit/pack into D-S4-20/26

Strong in-process

s4.6 D-S4-19 · s4.8 D-S4-26 · layout/items/emit-items.ts · layout/lanes/pack-lanes.ts

Before — two interfaces

emitItems(all PlannedRow[])
packLanes(all Item[])
// D-S4-19 sketch
getHeight → emit+pack one row

After — one interface

emitRow(row) → Item[]
packRow(items) → LanePacking
FrameMemory memo
computeFrame places the window

Problem. D-S4-19’s batch interface is as wide as the old loop. D-S4-26 already names packRow. Deletion test: delete the batch functions and complexity stays in getHeight.

Solution. Rewrite the D-S4-19 sketch to match D-S4-20/26. One per-row seam. Tests hit packRow and the memo, not a second whole-list adapter.

  • locality: pack lives in one module
  • leverage: height index and place share one memo
  • interface shrinks; implementation absorbs the window rule

A2 · Bind sort off declared Fields, not off gridColumns

Strong in-process

s4.3 D-S4-13 · s4.9 D-S4-28 · view/grid-columns.ts · layout/rows/sort.ts

Before — leak

sort reads presentation adapters. Hide the cost column, lose money compare.

After — two lists

columns = visible cells. fieldOrder (or one bound comparer for sort.field) = declared Fields. Same locale bind. No extra public knob.

Wins. Sort stays a data-order question. Grid stays a show question. Callers can sort by a Field they do not display.

A3 · Custom row source must not publish PlannedRow

Worth exploring in-process

s4.6 CustomRowSource.resolve → PlannedRowInput[] · README §5 “PlannedRow not public”

Problem. The expert occupant’s interface is the internal pipeline type. That is a leaked implementation. App authors who use source: 'custom' must learn kind, entryIds, headerLabel.

Solution. A small public row DTO as the custom-source interface (ids + entry ids + optional label), adapted once in custom-source.ts. Or keep PlannedRowInput as the expert type and name it on the public surface — do not claim it is internal.

Wins. locality: pipeline shape can change behind the adapter. One occupant today, S6 workload views later — two adapters justify the seam.

A4 · Pick X2 before group-source.ts

Strong in-process

Rename the row literal to 'header' (A) or keep 'group' (B). A removes the homonym at the one place cells skip format(entry). B is cheaper and leaves a durable agent trap. Do not implement grouping headers against a literal that may change.

Caller · foot-guns · core coupling

The common call is simple

README §5 still reads as one Dataset constructor and one Gantt constructor. { key: 'cost', type: 'money' } plus gridColumns: ['name', 'start', 'cost'] is the AG Grid split without putting aggregates on columns. Defaults keep S1’s look: ['name'], tree: false, autoGroup: false, heightMode: 'fixed', rollUpKinds: ['group']. Illegal pairs stay unrepresentable: sort/filter live on the row source, not on the Gantt (D-S4-28).

Foot-gun table is strong; four residuals

  • fromJSON merge (Sp3) — silent wrong Aggregator after reload.
  • Sort without a visible column (Sp2) — silent fallback order.
  • README sample turns autoGroup on — first reparent writes kind and then start/end in one changeset. Correct. Easy to copy into production. Default remains false; keep that in the comment.
  • Group header blanks — documented. Workaround “write through a group Entry” does not fill { source: 'group' } headers; those rows have no Entry. A computed Field also has no home on a header. Leave the blanks; do not invent view aggregates (D-S4-11).
