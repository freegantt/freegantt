F1 medium architecture · simplicity · spec · pass 2: Confirmed Strong

daysOfWeek() walks day boundaries, not days that intersect the window

src/extensions/features/time-shading-covers.ts:91-102 · src/time/zone.ts:85-93 · src/extensions/features/time-shading.ts:66-70 · src/extensions/features/time-shading-covers.ts:117

Problem. daysOfWeek asks time.eachDay(window). eachDay is a boundary walker: the first boundary at or after window.start. A decoration window starts wherever the pan left it. When that instant sits inside Saturday, Saturday's own midnight is before the window, so the walk begins on Sunday. clipToWindow cannot recover a day the walk never emitted. hours() already scans from the previous midnight; predicateSpans already steps one every back. The day-walking builder does not share that shape.

Probe (deleted). Chicago, Saturday 2026-06-06 10:00 → Monday. daysOfWeek(6, 7).coveredSpans returned a first band that starts Sunday 00:00, not 10:00 Saturday. notCovered(daysOfWeek(6, 7)) then painted Saturday 10:00–Sunday 00:00 — weekend afternoon as working time.

Solution. One intersecting-day walk behind the TimeCover seam: start at time.startOfDay(window.start), then clip. hours() keeps its extra day of overnight reach. Tests must use a window that starts mid-day; today's fixtures all start at midnight, so the miss cannot fail.
