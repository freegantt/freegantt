Problem. The Field-access module’s interface is nearly as wide as its implementation, and the storage fact still sits in every caller.

Solution. Deepen: readField, writeField, apply-onto-Entry, and “body proposed this Field” live in one module. Authored keys ride the edit or stay private. mergeEdits calls mergeStoredEdits.

  • Locality: one grep for where a value sits
  • Leverage: a fourth source changes one file
  • Tests hit that seam, not WeakMap reconstruction

2 · Fold effective tree and touched set into rollUpFields

Strong in-process

rollup.ts · transaction.ts

Before — caller orchestrates

buildEffectiveEntries
collectTouchedIds
rollUpFields(…, touched)

transaction.ts must learn which map is which.

After — D-S4-8 behind the seam

rollUpFields(committed, pending, registry, kinds, ctx)

Construction omits pending; commit passes pending. Helpers stay unexported.

Problem. The Rollup module is shallow at the call: the interface is the pipeline.

Solution. One interface. Construction and commit are two adapters of the same call. Do not export collectTouchedIds unless a test must name it — prefer asserting parent values after a bulk edit (Sp3).

  • Locality: ancestor walk lives with the pass
  • Leverage: construction and commit cannot drift

Does not contradict ADR 0005 or D-S2-22. Deepens D-S4-7: the leaf stays removable.
