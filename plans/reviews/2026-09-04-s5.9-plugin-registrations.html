That is not a missing generic; it is a missing named type for the ports object (the same pattern ColumnChromePorts already uses). Deepening candidates

One dispose contract for every register*

Strong in-process

src/view/gantt-shell.ts, src/layout/items/produce-items.ts, src/view/capability.ts, src/view/column-chrome.ts

Problem. Producer registration stacks the previous adapter and restores it; kind defaults last-write then delete on dispose; two plugin columns with the same field both append. Three seams, three dispose stories, one plugin author.

Solution. Deepen a small in-process registration table: register(key, value) → Disposer that always restores the previous value (or absence). Producers already are this table. Kind defaults and plugin columns become two more adapters of the same interface.

Top recommendation

One dispose contract for every register*, with glossary Item producer in the same pass.

S5.9 proved the open-kind claim. The remaining risk is not missing seams — it is three seams that look alike and unwind unlike. S5.10 will add Field / aggregator / type registers on the Dataset side; if dispose stays bespoke, the ball of mud is the registration tables, not the Gantt. The mapped KindDefaults type and the late-register tests are cheap follow-ups, not prerequisites.

Simplify — what not to do

  • Do not add plugin-host.ts. The slice already recorded that a second module would split one closure block for no seam this codebase draws.
  • Do not introduce ItemProducerContext. S4 shipped (entry) => readonly Item[]; this step is the way in, not a redesign.
  • Do not genericise PluginContextOf over kind or field. TGantt exists to break the gantt ↔ plugin import cycle. Extra type parameters would be speculative generality.
  • Do not publish wholeEntryItem just so the buffer plugin can call it. A third-party plugin is supposed to build an Item; that is the interface.
  • Do not fold plugin columns into gridColumnInput on register. The authored-list vs effective-list split is the D-S5-21 rule working.
