Stop rule — API gap in harness/

API gap tracked — status board line, one line to fix

harness/plugins/lock-entries.ts:87 — a hand-rolled refusal channel stands in for refuse(reason)

Core closed this in #210: beforeChange is Refusable, so a veto carries its words onto the mutation-cancelled report. The lock plugin still returns bare false and pages register locks.onRefusal(...) to toast by hand — harness/editing.ts:80 admits it: "One refuse(...) there retires that callback". This is the evidence-hiding case the Stop rule exists for: the compensating path keeps the worse API alive.

Folded in: the veto reports by: 'consumer', so the plugin's refusal reads as the page's own. ADR 0009 ruled the bus cannot know the refuser; the words on refuse(reason) are the mitigation — no ADR reopened.

Before — page-side compensation

return false;              // bare veto
announceRefusal?.(id);     // page toast
locks.onRefusal(handle);   // page wiring

After — the library's own record

return refuse(`Entry ${id} is locked`);
// words ride the mutation-cancelled
// report; onRefusal deleted
