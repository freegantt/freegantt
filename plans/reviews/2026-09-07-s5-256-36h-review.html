The two design points the WIP carried (A2 + A3), as it stood mid-review

A2 — two key-spaces, one concept

Gesture keys vs write keys share keyof Interactions; can('edit', entry) typechecks and routes a 2-arg write rule through a 1-field seam. One concept, two key-spaces.

A3 — the ladder eats structural refusals

interactions.edit overrides even a compute-sourced field's structural refusal → canWrite says WRITABLE, the write no-ops, the editor reports success. Silent no-op write.

Shape to land: narrow every capability seam to GestureCapability; put the two structural refusals (compute source, roll-up-derived field) below the override ladder — the consumer's edit rule overrides only the Field.editable default, the one thing it names.

  • the interface stops promising a write it cannot perform
  • the editor's "committed" verdict becomes trustworthy

Second pass — mud watch, API friendliness, self-documentation

Mud watch

  • One fact, two homes, three times: editable in registry vs Document (A4); the envelope triad named twice (T4/S4); nestsRows re-derived where the frame already states it (A5, WIP).
  • The error and command vocabularies grow as loose strings — mud pressure without a spine (T2/T3). One pattern fixes both.
  • The refusal ladder restates itself (canWrite/isOffered, S9). One precedence helper, or the ladder grows a third rung and forks.

API friendliness

  • gridWidth = 'fitColumns' fires cancelable from === to events on a no-op (B2). A consumer can veto nothing.
  • BuiltInCommandId's doc overstates its own guarantee — the compiler only catches typos at run() (T2).
  • extraEditsFor throws the one bare Error on the api surface (T8). Reachable never, off-family anyway.

Self-documentation

  • commitChangeSet's doc sits above beginStores — the transaction tail reads the wrong contract (S1).
  • readEdit's doc claims callers it does not have (S5); the export has no production caller.
  • harness/main.ts:191 admits in prose that sortByName is a second copy (A7). The comment knows; the code stays. That is the stop rule speaking — ask whether core closes it first.

Top recommendation

C1 — one reconcile loop with an on-refusal seam. It is a fix and a deepening at the same seam: the loop that raises InvertedSpanError into a rAF callback (B1, the window's only High) is the same twin body S2 wants gone. Fold the loops, raise a refusal as a report at commit, drop it at preview — and the extender seam's error contract, the one thing a plugin author cannot guess at today, lives in one place. Then take C3 (A4) before any release that demos the read-only End: the override is honored in memory and lost on disk, which is the worst kind of honest-looking gap.
