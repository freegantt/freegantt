F1 — A claimed parent's grandchildren keep their rows in flat mode

Verified by running code Correctness

src/layout/rows/entries-source.ts:108–111 (flat), :140–152 (tree)

tree: true

root      ← claimed
 └ child  → bar on root's row
    └ grand (no row)

rows = ['root']            ✔ J-plan-I

tree: false

root      ← claimed
 └ child  → bar on root's row
    └ grand → its own row

rows = ['root', 'grand']   ✘

Problem. The tree branch drops the whole subtree by not pushing a claimed parent's children onto the walk stack. The flat branch skips one level only — if (parentId !== undefined && claimedChildrenOf.has(parentId)) continue; — so a grandchild of a claimed parent still gets a row. The child's own bar already rolls up over that grandchild's span (README J-plan-I: "a direct child that has children of its own draws one bar whose span rolls up over them"), so the same work is drawn twice: once as a bar on the claimed row, once as a row of its own.

Why no test caught it. Every fixture that exercises a three-level claim uses childrenAsSegments: true, which claims every parent with children — so the middle Entry is claimed too and the grandchild is skipped as a direct child. The divergence only shows with a rule that claims one parent and not its child. 

// throwaway probe, run at 5d145ba, then deleted
const entries = entryDoubles([
  { id: 'root' },
  { id: 'child', parentId: 'root', start: 1, end: 2 },
  { id: 'grand', parentId: 'child', start: 1, end: 2 },
]);
const claimRootOnly = (entry) => String(entry.id) === 'root';

resolveEntriesSource(entries, { source: 'entries', tree: true,  childrenAsSegments: claimRootOnly })
  → ['root']            ✔
resolveEntriesSource(entries, { source: 'entries', tree: false, childrenAsSegments: claimRootOnly })
  → ['root', 'grand']   ✘  AssertionError: expected [ 'root', 'grand' ] to deeply equal [ 'root' ]

Ruling owed: is flat mode meant to collapse the whole subtree (matching tree mode and J-plan-I), or is a claim in flat mode deliberately one level deep? Either answer needs a test; only one needs a code change.

Pass 2 — Confirmed — and understated

The divergence reproduces. The ruling it asks for was already made.

The verifier reproduced both modes at entries-source.ts:111 (flat, direct parent only) against :153–155 (tree, never pushes a claimed parent's children): TREE ROWS [root] vs FLAT ROWS [root, grand]. The "why no test caught it" account also holds — entries-source.test.ts:60 is the only three-level claim test and it uses tree: true with childrenAsSegments: true. What does not hold is this finding's own proposal. No ruling is owed: plans/segment-is-a-bar/README.md:234 (J-plan-I) already says "the whole subtree below the claimed parent loses its rows", and entries-source.ts:2–3 claims the fold happens "in both modes". This is a plain defect against the spec and against the file's own header — patch it, do not ask.
