The maintainer comment calls it an intentional one-place fork; still the single most concrete cleanup in the diff.

  • Judgement — one word, two meanings GesturePipeline fields

    #pendingPreviewDraft (a draft awaiting the next rAF) and #pendingItemIds (entries held by an unsettled veto) both use "pending". Naming-skill check 4: same word, two concepts, one class. #pendingPreviewDraft predates this diff, but the async-veto work added the second "pending" beside it.     GesturePipelineDeps is correct DI, but GanttShell funnels its own state through closures (selection(), applyPreview, setPending writing #interactionState), so the pipeline reads shell-owned fields. Balanced: #draftFor/#commit reach only through deps. Not a violation.

Simplify

  • One fork, two bodies GesturePipeline.#commit

    Move and resize are the same pipeline twice with different event names. A single commit(gesture.discriminated) choosing the event names once would cut the branch and the duplicated finish closure. The maintainers' comment frames it as "isolated here" — true, but the isolation does not demand the body be written twice. Read the spec note in candidate A.

  • Coupling — drop vs paint behind pending D-S3-17 · #pendingItemIds + #preview(undefined)

    The spec's "lock vs paint" split is only half-realized: #pendingItemIds drives the arm lock and paint via setPending, but the dropped preview is cleared first. Two effects are fused in one field where the spec asked for two. Decouple: keep the dropped draft previewed while pending, and let the lock live beside it (candidate B).

  • Keep

    attachKeyboardEditing — the file owns its listener, so the call site "attach keyboard editing to the container" is true. nudge reads as the job. GesturePipeline over GestureHost. Sync-fast / async-slow #commit dual shape is a real constraint (undone draft in HANDOFF gotcha #5), not over-engineering.
