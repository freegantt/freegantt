# Editing Docs

`docs/` is the site. The site shell lives in [freegantt/docs](https://github.com/freegantt/docs).
It clones this repository at build time and reads `docs/` directly, so a page publishes by being
merged to `main`. There is no copy, no publish step, and nothing to keep in step.

This repository holds no Docusaurus files. The config, the sidebars, the CSS and the link plugin
are in freegantt/docs.

| Source                   | Route                                               |
| ------------------------ | --------------------------------------------------- |
| `docs/*.md`              | `/docs/<name>` — Docusaurus drops the number prefix |
| `docs/adr/*.md`          | `/docs/adr/`                                        |
| `docs/architecture/*.md` | `/docs/architecture/`                               |

`/api/` is the one exception. TypeDoc writes it from `src/` at site build, into a generated folder
in freegantt/docs. It has no source in `docs/`.

## Rules

1. Write the change in `docs/`. That is the whole publish step.
2. A new root guide needs an entry in `guidesSidebar` in freegantt/docs's `sidebars.ts`. Open that
   pull request there. The ADR and architecture sidebars are `autogenerated`, so a new page in those
   folders needs nothing.
3. Run `pnpm docs` to read your change in the browser. Run `pnpm docs:build` to prove the site still
   builds — `onBrokenLinks: 'throw'` fails it on a link that cannot land. Both keep a clone of
   freegantt/docs in `.docs-site/` (gitignored) and point it at this checkout.

## Two limits

- **Write a real relative path, never a site route.** A link to another page under `docs/` resolves
  by itself. A link that leaves `docs/` — `plans/`, `CONTEXT.md`, `README.md` — becomes a GitHub
  blob URL, and a link to `etc/freegantt.api.md` becomes the API reference.
  `plugins/link-outside-docs-to-github.mjs` in freegantt/docs does that, and it is the only
  rewriting left.
- **Give each page one `# …` heading and no front matter.** Docusaurus takes the title from the
  heading. One page carries front matter: `docs/00-guardrails-overview.md` holds `slug: /`, because
  it serves the docs root, `/docs/`. That is routing, not content.

## The architecture pages

`docs/architecture/` is prose about what `src/` does now. Read `docs/architecture/maintaining.md`
before you edit one. It says which page to update for each file you change.

Its `files.md` inventory is not generated — the "what it is for" column is prose a person writes
after reading the file. `test/guards/file-inventory.test.ts` holds it true instead: the test fails
when `src/` gains a file the page omits, when a row points at a deleted file, or when a row credits
a file with an export it does not contain. `pnpm guards` runs it, and `pnpm verify` runs that. Do
not build a second checker for it.

## The gate

`pnpm verify` does not build the site, by design — the site is a local concern. `pnpm docs:build`
is the check, and you run it when you change a link, a sidebar, or the Docusaurus config.

`test/guards/retired-words.test.ts` reads `docs/**`, so
prose there breaks CI exactly like code does.
